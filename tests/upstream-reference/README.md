# Upstream reference tests

Тесты, перенесённые из корня `tests/` при актуализации форка на
`davebcn87/pi-autoresearch` (rebase на `upstream/main`, v1.9.0).

## Почему они здесь

Эти тесты написаны апстримом и проверяют **модель апстрима**, от которой форк
намеренно отошёл:

1. **Гейтинг инструментов.** Апстрим (с #74/#90) скрывает все
   autoresearch-инструменты, пока сессия не активировала режим. Форк держит
   инструменты всегда доступными — иначе они не видны в headless/субагентных
   сессиях (коммит форка `54c7812`, нужен для кампаний). Тесты активации
   ассертят `activeTools() === []` до активации — на форке это не так.
2. **Реальные pi-пакеты.** Часть тестов вызывает `renderResult(...).render(w)`
   (Component-контракт pi-tui) и сериализует TypeBox-схемы. Форк гоняет тесты
   герметично, без `node_modules`, через заглушки (`tests/pi-tui-stub.mjs`,
   `tests/typebox-stub.mjs`), поэтому такие ассерты под стабами не работают.
3. **Супермножество автокомплита.** Форк объединил подкоманды апстрима
   (`finalize`, `dashboard`, `help`) со своими (`config`, `tree`,
   `parallel-*`), поэтому deep-equal на «ровно 6 подкоманд» апстрима не проходит.

## Как запускать

```bash
npm run test:upstream   # требует установленных зависимостей (pnpm install)
```

Ожидаемо красные там, где форк сознательно расходится с апстримом (см. выше) —
это документация расхождения, а не регрессия форка.
