# Stagnation Council — многоагентный совет при стагнации кампании

## 1. Цель и утверждённые решения

При стагнации autoresearch-кампании (N прогонов без улучшения) запускать совет из нескольких
моделей-аналитиков: они читают механический дайджест кампании, выдвигают гипотезы, ведут
**итеративный кросс-экзамен до консенсуса (cap 5 раундов)**, а «председатель» сводит итог в слейт
из 3–5 экспериментов. Кампания выполняет слейт обычным циклом (propose → run → log), арбитр —
бенчмарк.

**Утверждено владельцем:**
1. **Автотриггер** — наблюдатель запускает совет сам (плюс ручная команда `/autoresearch council`).
2. **Оба режима ростера**: «3 разные модели» и «N персон на одной модели» (модели не всегда
   доступны); режим определяется автоматически.
3. **Синтез — 4-й участник-председатель** (сильная модель), вызывается один раз, в конце.
4. **Доска — кастомные тула** в стиле `meeting_append_entry`, облегчённые (без JSONL-индекса).
5. **Кросс-экзамен — цикл до консенсуса**, cap 5 раундов; план составляется на финальном шаге.
6. **Ведущая модель кампании** — может класть на доску только записи-факты (Facts), оценивать
   гипотезы ей запрещено (по умолчанию таких записей нет; защита от ре-якорения на локальный
   оптимум, из которого совет и выводит).

Паттерн-референс: pi-brainstorm (D:/Documents/Repositories/pi-brainstorm) — blackboard-first,
фасилитатор-промпт вместо оркестрации кодом, WROTE_ENTRY-маркер, протокол отказов с ретраями.

Терминология: аналитики — обычные **субагенты** (тул `subagent` = headless-процесс pi со свежим
контекстом, своей моделью и read-only тулами). Никакой другой механики не используется.

## 2. Доска: кастомные тула, облегчённые

`council_write_entry`, `council_read_index`, `council_read_entry`.

- Запись = один markdown-файл `entries/<seq>-<speaker>.md` с YAML-шапкой
  (speaker / phase / summary) + полный текст. **Без JSONL-индекса и очередей**: read_index парсит
  шапки файлов каталога (≤10 файлов) — параллельная запись из отдельных процессов не может
  ничего повредить, консистентность обеспечена самой файловой структурой.
- promptGuidelines тулов сами учат протоколу: «пиши полный вклад на доску, в чат — только
  WROTE_ENTRY: <summary>».
- Path-safety: всё заперто в `.auto/councils/**` (assertPathInside, запрет symlink — как в
  pi-brainstorm).
- Допущение «дочерние субагенты видят глобально зарегистрированные тула pi-autoresearch»
  проверяется **гейт-экспериментом E1 до основной разработки** (§6); fallback-дизайн описан там же.

## 3. Архитектура

### 3.1 Каталог совета
```
.auto/councils/
  state.json                    # { councils_run, last_council_run, outcomes[] } — переживает сессии
  <seq>/
    00-brief.md                 # механический дайджест кампании (см. 3.4)
    entries/0001-AnalystA.md    # шапка: speaker/phase/summary + полный текст
    05-slate.md                 # финальный слейт председателя
```

### 3.2 Триггер
- **Авто**: `checkCouncilTrigger` в наблюдателе — decidedRuns ≥ `council.stagnation_runs`
  (дефолт 10) И cooldown пройден (≥ `council.cooldown_runs` (5) прогонов с конца совета ИЛИ был
  keep после совета) И `councils_run < council.max_councils` (3). Приоритет: сразу после
  stagnation — совет замещает обычную стагнационную подсказку.
- **Ручной**: `/autoresearch council` — тот же путь.
- Срабатывание = запись брифа + state.json + императивный followUp/steer агенту с
  фасилитатор-протоколом. `council.enabled=false` выключает всё.

### 3.3 Ростер (оба режима)
Конфиг в `.auto/config.json`:
```json
"council": {
  "enabled": true,
  "participants": [
    {"name": "AnalystA", "model": "anthropic/claude-haiku-5-5",  "persona": "patterns"},
    {"name": "AnalystB", "model": "zai-coding-cn/glm-5.3-flash", "persona": "explorer"},
    {"name": "AnalystC", "model": "openai-codex/gpt-6-luna",     "persona": "skeptic"}
  ],
  "chair_model": "zai-coding-cn/glm-5.3:high",
  "stagnation_runs": 10, "cooldown_runs": 5, "max_councils": 3
}
```
- **Автоопределение режима**: модели участников различны → каждая задача субагента со своей
  моделью (3 параллельно); совпадают (или явный `mode: "personas"`) → режим персон: одна модель,
  3 стойки, запуск 2+1 (лимит живых субагентов на модель).
- **Персоны-пресеты**: `patterns` (паттерны ledger/ASI, повторяющиеся причины провалов), `explorer`
  (нетронутые направления, читает код), `skeptic` (шум, риск, kill-criteria).
- **Деградация**: участник недоступен → ретрай ×2 (последний на дефолтной модели) → UNAVAILABLE,
  совет продолжается; <2 аналитиков → отмена совета, агенту — обычная стагнационная подсказка.

### 3.4 Бриф (механический, из ledger — не из памяти агента)
Цель/метрика/единица/направление; baseline, best, noise floor, число прогонов; таблица последних N
прогонов (статус/метрика/description/finding); цепочка keep'ов (путь из дерева); агрегат
do_not_retry из ASI; untried ideas; **исходы прошлых советов** (что предлагали, что дало);
benchmark guardrail.

### 3.5 Фазы (фасилитатор-протокол в steer/followUp агенту)

1. **Diverge** (1 раунд): 3 аналитика (субагенты, fresh, read-only + council-тула) читают бриф,
   каждый пишет ОДНУ запись с 3 гипотезами {гипотеза; evidence из брифа; ожидаемый эффект числом;
   стоимость}. Ответ: `WROTE_ENTRY: <summary>`.
2. **Challenge — цикл до консенсуса (cap 5 раундов)**:
   - Раунд r: каждый аналитик читает записи раунда r−1 и разбирает **только ещё спорные**
     гипотезы: disposition accept/reject/refine + причина + оценки эффект/сложность/риск.
     Свои гипотезы не защищает.
   - **Консенсус механический**: гипотеза решена, когда все остальные аналитики дали вердикт и
     открытых refine-вопросов нет. Фасилитатор проверяет чтением шапок доски — без вызовов моделей.
   - **Ранний выход**: спорных нет и жизнеспособных ≥ 3 → к фазе 3. Типично 2 раунда.
   - Ведущая модель может между раундами добавить запись `Facts` (только факты: шум, constraints;
     оценки гипотез ей запрещены). По умолчанию записей нет.
3. **Converge**: председатель (`chair_model`, один вызов) читает бриф + все записи, пишет
   `05-slate.md`: 3–5 экспериментов {гипотеза; почему-сейчас (evidence); ожидаемый эффект ≥ 2×
   noise floor; сложность; kill-criterion; проверка guardrail}, приоритизированы. Если после 5
   раундов консенсуса нет — берёт лучшее по числу accept'ов и помечает спорные.
4. **Исполнение кампанией**: агент читает слейт, регистрирует через `propose_hypothesis`
   (SimHash-дедуп), гонит обычный run/log; итог совета (был ли keep из слейта) пишется в
   state.json и попадает в бриф следующего совета.

### 3.6 Протокол отказов (из pi-brainstorm)
Успех записи = видна в `council_read_index` (агент проверяет после каждой пачки). Нет — ретрай ×2;
исчерпано → UNAVAILABLE; <2 аналитиков → отмена совета. У каждой задачи субагента — таймаут.

## 5. Шаги реализации

1. **E1 (гейт-эксперимент, до кода)**: probe в scratch-проекте — зарегистрировать тула, запустить
   1 субагента, убедиться, что он видит и зовёт council-тула. Если НЕТ — fallback: записи на доску
   делает сам фасилитатор-агент (тула доступны ему), аналитики возвращают текст результатом
   субагента; согласовать с владельцем до продолжения.
2. `council-tools.ts` + смоук (write/read/index, шапки, path-safety).
3. `council.ts`: бриф + ростер + детектор консенсуса + валидатор слейта + фасилитатор-сообщение; смоук.
4. Триггер + state.json + `/autoresearch council` + followUp; смоук условий.
5. SKILL.md + prompt-блок; полный npm test; ручной E2E на scratch-кампании (E3).
6. Коммит, push, `pi update --extensions`.

## 6. Верификация

**Смоук**: билдер брифа (все секции, детерминирован); триггер (10-й прогон / 9-й нет / cooldown /
cap / enabled=false); тула (запись, шапка, read_index, path-escape отклоняется); ростер (distinct →
per-task model; одинаковые → persona 2+1; инвалид → UNAVAILABLE); **детектор консенсуса** (решена/
спорная; ранний выход; cap 5 → best-effort); валидатор слейта (3–5, эффект ≥ 2×noise,
kill-criterion); фасилитатор-сообщение (фазы, WROTE_ENTRY, Facts-правила).

**E2/E3 (вручную)**: совет на scratch-кампании с посаженным ledger: бриф → diverge → ≥1 раунд
challenge → слейт → дедуп → прогон. Латентность (цель ≤ 5–10 мин на дешёвых моделях при 2 раундах).

## 7. Риски и дефолты

- **Дети не видят council-тулов** → E1 до старта; fallback описан.
- **Вежливость кросс-экзамена** → обязательные disposition'ы с числами; цикл до консенсуса
  выдавливает «согласен-просто-так»: refine обязывает ответить предметно.
- **Дорогой длинный спор** → narrowing (только спорные), ранний выход, cap 5; типично 2 раунда.
- **Ре-якорение на ведущую модель** → Facts-записи без права оценки; по умолчанию пусто.
- **Квота председателя** → деградация на дешёвую модель.
- **Совет не улучшил** → исход в state.json, виден следующему брифу; после max_councils — обычные
  подсказки.
- **Дефолты**: enabled=true после зелёного E3 (до того флаг выключен), stagnation_runs=10,
  cooldown_runs=5, max_councils=3, эффект ≥ 2×noise.
