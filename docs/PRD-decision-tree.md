# PRD: Decision Tree для autoresearch

> **Статус:** Draft
> **Версия:** 1.0
> **Связанные документы:** [ТЗ](./TZ-decision-tree.md)

---

## 1. Проблема

Текущий autoresearch — **жадный hill-climb с амнезией**.

Агент экспериментирует линейно: одна гипотеза → keep/revert → следующая. Параллельные
инструменты (BestOfN, SpaceSearch) создают временные ветки, но после выбора победителя
**все альтернативы уничтожаются** — коммиты, диффы, гипотезы.

Это приводит к пяти проблемам:

| # | Проблема | Последствие |
|---|----------|-------------|
| 1 | **Нет памяти exploration** | Агент может повторить проваленную гипотезу через 20 экспериментов |
| 2 | **Нет бэктрекинга** | Нельзя вернуться к развилке и попробовать другой путь |
| 3 | **Нет композиции** | Нельзя сложить два ортогональных улучшения из разных веток |
| 4 | **Агент слеп к карте** | Не знает форму своего поиска: сколько веток исследовано, где тупики |
| 5 | **Хорошие идеи умирают** | Если воркер криво реализовал гипотезу (crash), идея пропадает навсегда |

---

## 2. Видение

**Persistent Experiment Tree** — каждое эксперимент оставляет след в дереве решений.
Агент (и пользователь) в любой момент видит всю карту исследования, может вернуться
к любой развилке, попробовать альтернативу, скомбинировать найденные улучшения.

Дерево — это **слой навигации и памяти**, а не новый алгоритм поиска. Существующий
flow (run_experiment → log_experiment) не меняется — он обогащается структурой.

---

## 3. Цели / Не цели

### Цели (v1)

- [ ] Каждый эксперимент (keep/discard/crash) сохраняется как узел дерева
- [ ] Backtracking: `explore_from(node_id)` — вернуться к любой точке и исследовать оттуда
- [ ] Composition: `compose(nodeA, nodeB)` — объединить диффы из разных веток
- [ ] Повтор detection: предупреждение о похожих уже опробованных гипотезах (SimHash)
- [ ] UCB1-ранжирование узлов для выбора точки форка
- [ ] TUI-визуализация дерева с переключением list ↔ tree

### Не цели (v1)

- Полноценный MCTS auto-pilot (система сама генерирует и запускает гипотезы)
- Интеграция с BestOfN/SpaceSearch (опционально, phase 2)
- Семантический повтор detection (embeddings)
- Визуализация дерева в HTML dashboard
- Автономная работа без агента

## 4. Пользовательские сценарии

### Сценарий 1: Тупик и backtrack

**Контекст:** агент оптимизирует парсер, baseline 100µs. Сделал 4 эксперимента по
AST-кэшированию: первые 2 успеха (→88µs), последние 2 провала.

**Без дерева:** stagnation steer → агент «рефлексирует», часто продолжает долбить ту же идею
или пытает случайные вариации.

**С деревом:**
1. tree_status показывает: «AST-ветка исчерпана (2 discard), n0 имеет только 1 ребёнка»
2. UCB1 предлагает: explore_from(n0) — попробовать fundamentally другой подход
3. Агент возвращается к baseline и пробует lookup table → 81µs (лучше!)

### Сценарий 2: Композиция

**Контекст:** агент нашёл два улучшения на разных ветках:
- n1 «AST cache»: 100 → 92µs (-8µs)
- n5 «lookup table»: 100 → 81µs (-19µs)

**Без дерева:** агент забыл про n1 после переключения на lookup.

**С деревом:**
1. Агент видит дерево: две ортогональные ветки, меняют разные файлы
2. compose(n1, n5) → система накладывает оба диффа → 72µs (-28%!)
3. Три независимо найденных улучшения сложены в одно

### Сценарий 3: Предотвращение повтора

**Контекст:** агент вернулся к n0 (backtrack). Его LLM-контекст помнит AST-идею.

**Без дерева:** агент снова пробует «AST cache» → тратит эксперимент впустую.

**С деревом:**
1. run_experiment({ hypothesis: "add AST cache" })
2. SimHash проверяет: n1 имеет hypothesis "AST cache", distance=0 → EXACT MATCH
3. Предупреждение: «n1 уже пробовал это (keep, 92µs). Уточни гипотезу.»
4. Агент выбирает другое направление

### Сценарий 4: Ручная навигация пользователем

**Контекст:** пользователь открыл TUI, видит дерево экспериментов.

**Без дерева:** плоский список экспериментов по номеру.

**С деревом:**
1. Пользователь нажимает Tab → переключается в tree view
2. Видит иерархию: какие подходы пробовались, где тупики, какой путь лучший
3. Нажимает Tab → обратно в list view (хронологический)

## 5. UX: TUI-визуализация

### Два вида, переключаемые Tab

**List view (текущий, без изменений):**
```
 #15  keep   88µs  (-4)  "LRU eviction"            [2h ago]
 #14  keep   92µs  (-8)  "AST cache"               [2h ago]
 #13  discard 93µs (--)  "bigger cache"            [3h ago]
 ...
```

**Tree view (новый):**
```
 n0  100µs  baseline
 ├── n1  92µs  ●  "AST cache"           keep  -8µs
 │    ├── n2  88µs  ●  "LRU eviction"   keep  -4µs
 │    │    ├── n3  88µs  ○  "bigger"    discard
 │    │    └── n4  89µs  ○  "precompute" discard
 │    └── n5  90µs  ●  "hash table"     keep  -2µs
 ├── n6  81µs  ●  "lookup table"        keep  -19µs ★
 │    └── n7  78µs  ●  "precompute tok" keep  -3µs
 └── n8  72µs  ◆  "compose(n1,n7)"     keep  -28µs ★★

 ● keep   ○ discard   ✕ crash   ◆ compose   → active
```

### Цветовое кодирование

| Элемент | Цвет | Значение |
|---------|------|----------|
| Best path (★) | Зелёный, bold | Лучший путь от baseline |
| Keep (●) | Зелёный | Успешный эксперимент |
| Discard (○) | Dim/gray | Провален (без улучшения) |
| Crash (✕) | Красный | Упал (код не работает) |
| Compose (◆) | Синий | Результат композиции |
| Active (→) | Жёлтый, bold | Текущий узел агента |
| Exhausted branch | Dim + ☒ | Ветка помечена исчерпанной |

### Взаимодействие

| Клавиша | Действие |
|---------|----------|
| `Tab` | Переключение list ↔ tree |
| `↑` `↓` | Навигация по узлам дерева |
| `Enter` | Детали узла (hypothesis, ASI, diff summary, simhash) |
| `e` | `explore_from` выбранного узла |
| `c` | `compose` mode (выбрать 2 узла) |

## 6. Метрики успеха

| Метрика | Как измеряем | Цель |
|---------|-------------|------|
| **Repeat rate** | % экспериментов, которые система пометила как repeat (post-hoc) | < 5% после внедрения |
| **Backtrack adoption** | % сессий, где агент использовал explore_from ≥1 раза | > 30% сессий > 10 экспериментов |
| **Composition wins** | Количество compose(), давших улучшение | > 0 (новая возможность) |
| **Stagnation recovery** | % случаев, когда после stagnation агент сменил ветку | > 60% (было ~0%) |
| **Exploration breadth** | Среднее число веток (children of root) на сессию | ≥ 2.5 |
| **TUI engagement** | Ручные переключения в tree view пользователем | Отслеживание (не цель) |

## 7. Развитие (после v1)

### Phase 2: Интеграция с параллельными инструментами

- BestOfN создаёт N дочерних узлов (проигравшие сохраняются как dead branches)
- SpaceSearch строит поддерево, pruned states остаются в дереве
- mcts_round(): UCB1 select + BestOfN expand

### Phase 3: Автоматизация

- Hypothesis generation helper (LLM-assisted, из backlog + tree analysis)
- Auto-exhausted pruning (GC dead branches после N шагов)
- Semantic repeat detection (embeddings вместо simhash)
