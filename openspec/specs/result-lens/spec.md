# result-lens Specification

## Purpose
Сохранение полного вывода прогонов и артефактов, инструмент inspect_results и экстракторы метрик без раздувания контекста агента.

## Requirements

### Requirement: Персистенция полного вывода прогона
Система SHALL сохранять полный вывод каждого `run_experiment` в `.auto/runs/<номер>/output.txt` вместо временного файла ОС, включая случаи, когда вывод обрезан в ответе инструмента.

#### Scenario: вывод обрезан
- **WHEN** вывод эксперимента превышает лимит инструмента (строки/байты) и в ответе показан только хвост
- **THEN** полный вывод доступен в `.auto/runs/<n>/output.txt`, и ответ инструмента содержит путь к нему

#### Scenario: крах эксперимента
- **WHEN** эксперимент падает (crash/timeout/kill)
- **THEN** накопленный к моменту краха вывод сохранён в `.auto/runs/<n>/output.txt`

### Requirement: Персистенция заявленных артефактов
Система SHALL копировать в `.auto/runs/<n>/` артефакты, объявленные в секции `analysis.artifacts` конфига кампании, если они существуют после прогона, и записывать манифест `.auto/runs/<n>/manifest.json` (пути, размеры, sha16).

#### Scenario: артефакт объявлен и создан
- **WHEN** команда прогона создала файл, указанный в `analysis.artifacts`
- **THEN** копия файла лежит в `.auto/runs/<n>/` и перечислена в manifest.json

#### Scenario: артефакт не создан
- **WHEN** объявленный артефакт отсутствует после прогона
- **THEN** это фиксируется в manifest.json как missing; прогон не считается упавшим из-за этого

#### Scenario: артефакт превышает лимит размера
- **WHEN** размер артефакта превышает конфигурируемый потолок копирования
- **THEN** в манифест записывается только путь-ссылка на оригинал (без копии), с пометкой size-only

### Requirement: Инструмент inspect_results
Система SHALL предоставлять tool `inspect_results` с аргументами `run` (номер прогона; по умолчанию — лучший keep-прогон текущей эпохи), `extractor` (имя экстрактора; по умолчанию — все generic) и `page`, читающий ТОЛЬКО персистированные выводы `.auto/runs/` и возвращающий bounded-сэмпл для чтения агентом.

#### Scenario: инспекция лучшего прогона
- **WHEN** агент вызывает `inspect_results` без аргументов
- **THEN** возвращается сэмпл из лучшего keep-прогона текущей эпохи: METRIC-строки, сэмплы по экстракторам, указатели на полные файлы; если такого keep нет, возвращается явное сообщение и предлагается указать номер прогона

#### Scenario: нет персистированных прогонов
- **WHEN** кампания велась до внедрения (`.auto/runs/` пуст)
- **THEN** tool возвращает объяснение и совет перезапустить замер через `run_experiment`

### Requirement: Generic-экстракторы
Система SHALL поддерживать встроенные экстракторы, работающие в любом домене без конфигурации:
- **METRIC-строки** — существующий парсер;
- **error/warn** — строки с подстроками `error|fail|warn` без учёта регистра;
- **timing top-N** — строки, содержащие число и следующую за ним единицу из множества {`ms`, `µs`, `us`, `s`} на границе слова; значение нормализуется в миллисекунды, строки сортируются по убыванию значения, возвращается top-N;
- **дельты против лучшего** — построчное сравнение вывода указанного прогона с лучшим keep-прогоном той же эпохи; максимум 200 строк до пагинации. Если такого прогона нет, дельта не считается и возвращается объяснение. При разнице объёмов выводов более 2× возвращается head/tail-сэмпл обоих с пометкой о несоизмеримом объёме. Если ни один экстрактор не нашёл данных, возвращается сырой head/tail-сэмпл с соответствующей пометкой.

#### Scenario: perf-домен без конфигурации
- **WHEN** кампания оптимизирует время выполнения и `analysis`-секция не задана
- **THEN** сэмпл содержит top-N строк, отсортированных по нормализованному времени (µs и s пересчитаны в ms), и различающиеся строки против лучшего прогона

#### Scenario: лучший прогон только в другой эпохе
- **WHEN** в текущей эпохе нет keep-прогона, но он есть в предыдущей
- **THEN** дельта не рассчитывается и ответ объясняет отсутствие сопоставимой базы

#### Scenario: нет совпадений экстракторов
- **WHEN** экстракторы не нашли результатов
- **THEN** возвращается ограниченный сырой head/tail-сэмпл с пометкой

#### Scenario: несоизмеримые объёмы выводов
- **WHEN** объём вывода инспектируемого прогона более чем в 2 раза отличается от лучшего
- **THEN** вместо построчных дельт возвращается head/tail-сэмпл обоих выводов с пометкой

### Requirement: Конфигурируемые экстракторы кампании
Система SHALL применять экстракторы из секции `analysis.extractors` конфига кампании (regex с именованными группами, top-N сэмплы, json_path по JSONL-артефактам) поверх generic.

#### Scenario: доменное окно ошибок
- **WHEN** `analysis.extractors` объявляет regex для строк MISMATCH с gold/pred-группами
- **THEN** сэмпл `inspect_results` содержит пары gold/pred из объявленного экстрактора

#### Scenario: некорректный regex в конфиге
- **WHEN** `analysis.extractors` содержит невалидный regex
- **THEN** ошибка конфигурации сообщается при инициализации сессии/первом использовании, а не молча игнорируется

### Requirement: Ограничение объёма ответа
Ответ `inspect_results` SHALL быть ограничен (по умолчанию ≤200 строк / ≤8KB) с поддержкой постраничного продолжения, чтобы агент читал сэмпл целиком, а не оставался без данных.

#### Scenario: сэмпл больше лимита
- **WHEN** экстрактор возвращает больше строк, чем лимит
- **THEN** ответ содержит первую страницу, общий счётчик и подсказку следующей страницы
