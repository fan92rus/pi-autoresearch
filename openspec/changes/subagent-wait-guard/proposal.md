# Proposal

## Why

Когда агент кампании запускает субагента (например, независимого ревьюера) асинхронно, ход может завершиться без полезной работы цикла: агент заканчивает ход ответом «жду субагента» или занимает ходы повторными просмотрами состояния. Механика drift-resume тогда пинает агента впустую: каждый пустой ход сжигает лимит возобновлений и засоряет транскрипт. В pi-goal-x (коммит `0449563`) эта проблема решена на двух уровнях — промпт-инструкция держать ход открытым через `bg_wait` и механическая отсрочка continuation при живых async-субагентах. Тот же паттерн переносится в autoresearch.

## What Changes

- Промпт обычного цикла получает одну строку: при летящем async-субагенте держать ход открытым через `bg_wait` (перевзводить по таймауту) вместо завершения хода ответом «waiting».
- Перед отправкой drift-resume (пустой ход без работы цикла) расширение проверяет через pi-subagents RPC, есть ли живые async-субагенты; если есть — nudge откладывается, а не доставляется.
- Отложенный nudge доставляется, когда повторная проверка (по событию завершения `subagent:async-complete`, по таймеру 30 с) не показывает живых async-субагентов, или по истечении предохранителя (10 мин непрерывного ожидания); при недоступности pi-subagents поведение не меняется (fail-open).

## Capabilities

### New Capabilities
- `subagent-wait-guard`: удержание хода и отсрочка nudge при живых async-субагентах.
