# Design: research-charter (MVP)

Уровень деталей — MVP. Поведение и инварианты зафиксированы в спеке; здесь только ключевые решения и их причины.

## Решения

1. **Источник истины — хеш из аргументов или диалога.** Файл хартии без ожидаемого хеша ничего не значит. Причина: в `research-vectors` подтверждение лежит в рабочей директории агента, и защита сводилась к сверке SHA с файлом. Здесь ожидаемый хеш приходит от владельца извне, и агент не может подменить одновременно файл и хеш.

2. **Хартия вне рабочей директории.** Проверяется по пути, а не по содержимому. Причина: агент с записью в рабочую директорию может переписать файл хартии; вне неё такой путь закрыт для инструментов расширения. Прямая запись через shell остаётся остаточным риском, как и раньше.

3. **Автоподтверждение только механических проверок.** Инструмент проверяет схему, равенство блока ограничений, вердиктов и `evidence_gate`, наличие ссылок на находки цепочки и лимиты. Суждение «вопрос логично следует из находки» остаётся за агентом и в журнал не выдаётся как проверенный факт.

4. **Журнал `chain.json` append-only.** Решения цепочки читаются при каждом действии. Повреждение или расхождение хеша переводит в `manual_check_required`, как и в `research-vectors`.

5. **Режим между кампаниями.** Промежуточный отчёт сохраняет режим, иначе агент не сможет открыть следующую кампанию: все инструменты исследования отказывают при выключенном режиме.

## Не делаем в MVP

- Отдельный интерфейс для просмотра цепочки (достаточно `chain.json`).
- Автоматическое переформулирование вопросов или выбор вопросов по весу находок.
- Бюджет по токенам и времени.

## Открытые вопросы для ревью владельца

- Значения по умолчанию лимитов: 5 кампаний и глубина 4. Подтвердить или поправить.
- Разрешён ли статус `waiting_for_data` как основание для дочернего брифа (в спеке — да, как находка без подтверждения).
