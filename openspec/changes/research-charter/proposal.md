# Proposal: research-charter

Ревизия: rev.2 (цикл ревью, раунд 1 — см. журнал `.auto/spec-reviews/research-charter/LOG.md`)

## Why

Сейчас каждая исследовательская кампания требует отдельного подтверждения брифа владельцем (диалог `ctx.ui.confirm`), а вопросы фиксированы брифом. Поэтому агент не может сам продолжить исследование: после отчёта кампании он не запускает следующую, даже когда находки ведут к новым вопросам. Владелец хочет, чтобы агент итеративно проводил исследования: из находок одной кампании строил бриф следующей и так далее, без подтверждения на каждом шаге, но в пределах заранее согласованных рамок.

## What Changes

- Владелец один раз подтверждает **хартию исследования** — файл с лимитами цепочки и правилами автоподтверждения. В headless-режиме ожидаемый хеш хартии задаётся аргументом запуска; в интерактивном — диалог показывает `Charter SHA-256: <hex>` и сводку лимитов, и система пере-хеширует файл в момент подтверждения. Модель не передаёт ожидаемый хеш и поля одобрения.
- Агент в цепочке закрывает кампанию (`stop`, `report`), затем пишет бриф следующей кампании из находок предыдущей. **Находка цепочки** — вопрос, закрытый в кампании этой цепочки вердиктом из набора брифа; ссылка на неё — механическая проверка по журналу цепочки. Бриф подтверждается автоматически, если проходит проверку хартии: лимиты, неизменность блока ограничений, эффективных наборов вердиктов и `evidence_gate`, ссылки вопросов на находки цепочки.
- Дельта `research-vectors` модифицирует требования, которым противоречит автоподтверждение: «Подтверждение только пользователем» (исключение для брифов цепочки с provenance в `approval.json`), «Стоп-правила» (новая фаза согласования кампании цепочки = автоподтверждённый бриф по хартии), «Продолжение исследования» (одно продолжение к следующему брифу), «Архив завершённых кампаний» (кампании активной цепочки не архивируются). Остальные требования без изменений.
- Цепочка ведёт журнал решений (`chain.json` в каталоге цепочки вне каталогов кампаний, append-only с хеш-цепочкой записей). Статусы цепочки собраны в одном требовании: `active`, `awaiting_child`, `completed`, `limit_reached`, `stopped_by_owner`, `stopped_by_rule`, `manual_check_required`. Остановка — по лимиту, по стоп-правилу хартии, по команде владельца `research chain_stop` (диалог оператора, как `resolve`) или при расхождении хеша/повреждении журнала.
- Режим исследования остаётся включённым между кампаниями цепочки и выключается только отчётом кампании, после которого цепочка не может продолжаться; остановка цепочки без отчёта режим не выключает.
- Headless-обёртка `scripts/research-rpc.mjs`: `--charter` и `--approve-charter-sha`; промежуточный отчёт цепочки не завершает запуск — обёртка доставляет продолжение и ждёт следующего действия; идентификаторы кампаний цепочки назначает система; отказ хартии — новый код выхода 3.

## Out of Scope

- Автоматическое подтверждение без хартии (всё по-прежнему требует владельца).
- Изменение вердиктов, правил закрытия и `evidence_gate` внутри цепочки.
- Временной и бюджетный лимит по токенам (по-прежнему не вводится, как в `research-vectors`).
- Параллельные кампании: цепочка линейная, одна активная кампания за раз, у каждой кампании не более одного потомка.
- Обзор направлений и типы активности — это `research-map`, не этот change.
- Защита от агента, который пишет произвольные файлы через shell: это остаточный риск, как и для `research-vectors`; защита опирается на хеш из аргументов запуска и обнаружение несогласованности с переводом в `manual_check_required`.
- Возобновление прерванной цепочки: после прерывания запуска цепочка остаётся в своём статусе; продолжение требует нового запуска с хартией и команды владельца.

## Capabilities

### New Capabilities
- `research-charter`: хартия владельца, автоподтверждение брифов цепочки, журнал цепочки, статусы и остановка, включая команду `research chain_stop`.

### Modified Capabilities
- `research-vectors`: модифицируются «Подтверждение только пользователем», «Стоп-правила», «Продолжение исследования», «Архив завершённых кампаний при новом запуске», «Выход из режима исследования после отчёта» — только в части, касающейся цепочек. Остальные требования без изменений.

## Impact

- `extensions/pi-autoresearch/` — модуль хартии и журнала цепочки; `research` получает действие `chain_stop` (диалог оператора); `research_brief` — проверку хартии для брифов цепочки; `report` и `status` учитывают цепочку; `approval.json` автоподтверждённых брифов пишется системой с источником `charter`.
- `scripts/research-rpc.mjs` — аргументы `--charter`, `--approve-charter-sha`; поведение при промежуточном отчёте цепочки; распознавание диалога `Charter SHA-256:`; код выхода 3 при отказе хартии.
- `docs/research-vectors.md` — раздел про цепочку (после реализации).
- Совместимость: кампании без хартии работают как раньше; коды выхода существующих сценариев не меняются.
