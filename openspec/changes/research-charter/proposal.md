# Proposal: research-charter

Ревизия: rev.3 (цикл ревью, раунды 1–2; решение владельца 2026-11-10 — цепочка по умолчанию без лимитов)

## Why

Сейчас каждая исследовательская кампания требует отдельного подтверждения брифа владельцем (диалог `ctx.ui.confirm`), а вопросы фиксированы брифом. Поэтому агент не может сам продолжить исследование: после отчёта кампании он не запускает следующую, даже когда находки ведут к новым вопросам. Владелец хочет, чтобы агент итеративно проводил исследования: из находок одной кампании строил бриф следующей и так далее, без подтверждения на каждом шаге, но в пределах заранее согласованных рамок.

## What Changes

- Владелец один раз подтверждает **хартию исследования** — файл с правилами автоподтверждения. По решению владельца (2026-11-10) хартия по умолчанию **без лимитов**: цепочка неограниченная; лимиты (`max_campaigns`, `max_depth`) — опциональные поля, действуют только если заданы. В headless-режиме ожидаемый хеш хартии задаётся аргументом запуска; в интерактивном — диалог показывает `Charter SHA-256: <hex>` и сводку полей хартии, и система пере-хеширует файл в момент подтверждения. Модель не передаёт ожидаемый хеш и поля одобрения.
- Агент в цепочке закрывает кампанию (`stop`, `report`), затем пишет бриф следующей кампании из находок предыдущей. **Находка цепочки** — вопрос, закрытый с доказательством в любой кампании этой цепочки вердиктом из её эффективного набора; ссылка на неё — механическая проверка пары `campaign` + `question` по полю `finding_refs` вопроса и журналам кампаний цепочки. Бриф подтверждается автоматически, если проходит проверку хартии: схема, дословный блок ограничений, эффективный набор вердиктов, `evidence_gate`, ссылки на находки, лимиты (если заданы).
- Дельта `research-vectors` модифицирует требования, которым противоречит автоподтверждение: «Подтверждение только пользователем» (исключение для брифов цепочки с provenance в `approval.json`), «Стоп-правила» (новая фаза согласования кампании цепочки = автоподтверждённый бриф по хартии), «Продолжение исследования» (одно продолжение к следующему брифу), «Архив завершённых кампаний» (кампании активной цепочки не архивируются), «Выход из режима исследования после отчёта» (промежуточный отчёт режим не выключает; финальный отчёт кампании цепочки — выключает). Остальные требования без изменений.
- Цепочка ведёт журнал решений (`chain.json` в каталоге цепочки вне каталогов кампаний, append-only с хеш-цепочкой записей и отдельным файлом головного хеша). Статусы цепочки собраны в одном требовании: `active`, `awaiting_child`, `completed`, `limit_reached` (только при заданных лимитах), `stopped_by_owner`, `stopped_by_rule`, `manual_check_required`. Остановка — по стоп-правилу хартии, по команде владельца `research chain_stop` (диалог оператора) или при расхождении хеша/повреждении журнала.
- Режим исследования остаётся включённым между кампаниями цепочки и выключается отчётом кампании, после которого цепочка не может продолжаться; `chain_stop` в `awaiting_child` выключает режим немедленно (отчёт последней кампании уже сохранён).
- Headless-обёртка `scripts/research-rpc.mjs`: `--charter` + обязательный `--approve-charter-sha`; контракт аргументов и кодов выхода определён (отказ хартии — код 3 до создания какого-либо состояния); промежуточный отчёт цепочки не завершает запуск; пауза цепочки в `awaiting_child` — штатный выход с кодом 0.

## Out of Scope

- Автоматическое подтверждение без хартии (всё по-прежнему требует владельца).
- Изменение набора вердиктов, `evidence_gate` и блока ограничений внутри цепочки — запрещено. Тексты правил закрытия вопросов определяются брифом каждой кампании (вопросы в кампаниях разные); сравнение текстов правил между кампаниями не выполняется, инвариант цепочки — вердикты, `evidence_gate`, блок ограничений.
- Временной и бюджетный лимит по токенам (по-прежнему не вводится). Безлимитная цепочка по умолчанию — явное решение владельца (2026-11-10); стоимость неограниченной цепочки — принятый остаточный риск.
- Параллельные кампании: цепочка линейная, одна активная кампания за раз, у каждой кампании не более одного потомка.
- Обзор направлений и типы активности — это `research-map`, не этот change.
- Защита от агента, который пишет произвольные файлы через shell: это остаточный риск, как и для `research-vectors`; защита опирается на хеш из аргументов запуска и обнаружение несогласованности с переводом в `manual_check_required`.
- Возобновление прерванной цепочки: после прерывания запуска цепочка остаётся в своём статусе; продолжение требует нового запуска с хартией и команды владельца. Отдельного механизма отзыва хартии нет: остановка — `chain_stop`, изменение файла хартии обнаруживается сверкой хеша (`charter_changed`).

## Capabilities

### New Capabilities
- `research-charter`: хартия владельца, автоподтверждение брифов цепочки, журнал цепочки, статусы и остановка, включая команду `research chain_stop`.

### Modified Capabilities
- `research-vectors`: модифицируются «Подтверждение только пользователем», «Стоп-правила», «Продолжение исследования», «Архив завершённых кампаний при новом запуске», «Выход из режима исследования после отчёта» — только в части, касающейся цепочек. Остальные требования без изменений.

## Impact

- `extensions/pi-autoresearch/` — модуль хартии и журнала цепочки; `research` получает действие `chain_stop` (диалог оператора); `research_brief` — проверку хартии и поле `finding_refs` для брифов цепочки; `report` и `status` учитывают цепочку; `approval.json` автоподтверждённых брифов пишется системой с источником `charter`.
- `scripts/research-rpc.mjs` — аргументы `--charter` (требует `--approve-charter-sha`), поведение при промежуточном отчёте и паузе цепочки, распознавание диалога `Charter SHA-256:`, код выхода 3 при отказе хартии (без создания состояния).
- `docs/research-vectors.md` — раздел про цепочку (после реализации).
- Совместимость: кампании без хартии работают как раньше; коды выхода существующих сценариев не меняются.
