## 1. Хартия и согласование
- [x] 1.1 Тест: хартия без ожидаемого хеша не принимается; модель не может передать одобрение (allowlist параметров: любые неизвестные поля отклоняются); хартия с полем вне allowlist состава не принимается.
- [x] 1.2 Тест: realpath пути хартии внутри рабочего каталога отказывает (`charter_inside_workdir`), включая symlink/junction и регистр имён Windows.
- [x] 1.3 Тест: интерактивный диалог начинается с `Charter SHA-256: <hex>`, показывает поля хартии; при `ctx.hasUI = false` отклоняется; отказ владельца не фиксирует хартию.
- [x] 1.4 Тест: пере-хеширование в момент подтверждения — файл изменился между показом и подтверждением → подтверждение не фиксируется. Реализация: загрузка хартии, вычисление и сверка хеша, диалог подтверждения (строго `true`).
- [x] 1.5 Тест: состав хартии — `max_campaigns` ≥ 1, `max_depth` ≥ 0 (корень = 0), без них лимитов нет; поле `stop_rules` — массив строк; отказ при правилах смены вердиктов/`evidence_gate`/блока ограничений; хартия с неизвестным полем не принимается; линейность цепочки. Реализация: парсинг и валидация хартии.

## 2. Автоподтверждение брифов цепочки
- [x] 2.1 Тест: бриф, проходящий проверки, подтверждается автоматически; `approval.json` записан системой с источником `charter` и хешем хартии; решение записано в `chain.json` с хешем брифа, хешем хартии и снимком родителя (`caveat_block`, эффективный набор вердиктов, `evidence_gate`, id кампании). Реализация: автоподтверждение поверх `research_brief draft`.
- [x] 2.2 Тест: поле `finding_refs` вопроса — массив пар `{campaign, question}`; пустой/отсутствующий массив и пара на несуществующий или незакрытый-без-доказательства вопрос → `finding_missing`; вопрос, закрытый вердиктом `waiting_for_data` с записанным доказательством, принимается как находка.
- [x] 2.3 Тест: смена блока ограничений (`caveat_changed`); расхождение эффективного набора вердиктов или `evidence_gate` (`verdicts_or_gate_changed`, массивы как множества); бриф не проходит схему; родитель без `verdicts` + потомок с явным тем же набором — совпадение.
- [x] 2.4 Тест: при заданных лимитах превышение числа кампаний или глубины (корень = 0) → `limit_reached`; отчёт кампании, достигшей лимита → `limit_reached` + выключение режима; без лимитов проверки пропускаются на любой глубине и статус не достижим; повторная отправка подтверждённого брифа не создаёт вторую кампанию; бриф до отчёта родителя → `parent_not_reported`.
- [x] 2.5 Тест: исключение дельты «Подтверждение только пользователем» — автоподтверждённый бриф цепочки запускает фазу без диалога; вне цепочки поведение прежнее.

## 3. Журнал, статусы, остановка, ручная проверка
- [x] 3.1 Тест: append-only журнал с `prev_hash`-цепочкой; повтор не переписывает предыдущие записи; головной хеш в отдельном файле `chain-head` и сверяется при каждом действии; журнал в `<state-root>/research-chain/<id>/` вне каталогов кампаний.
- [x] 3.2 Тест: расхождение `chain-head`, повреждённый или отсутствующий `chain.json`/`chain-head` → `manual_check_required`.
- [x] 3.3 Тест: подмена файла хартии после подтверждения → `charter_changed` на каждом действии цепочки, статус `manual_check_required`.
- [x] 3.4 Тест: статусы цепочки (`active`, `awaiting_child`, `limit_reached`, `stopped_by_owner`, `stopped_by_rule`, `manual_check_required`, `completed`): начальный статус, финальные отказывают действия кроме `report` остановленной-во-время-работы цепочки, предикат «цепочка может продолжаться» (с перспективной проверкой лимитов).
- [x] 3.5 Тест и реализация `research chain_stop`: диалог оператора строго `true` (модель без подтверждения отклоняется); из `awaiting_child` — `stopped_by_owner` + немедленное выключение режима; из `active` — новые брифы отказывают, открытый вектор не прерывается.
- [x] 3.6 Тест: стоп-правило хартии (самоотчёт агента) → `stopped_by_rule`; во время кампании — финальный отчёт активной кампании выключает режим; в паузе — режим выключается немедленно.
- [x] 3.7 Тест: исключение дельты «Стоп-правила» — стоп-правило кампании цепочки + отчёт + следующий бриф считаются новой фазой согласования без диалога; `chain_stop`/стоп-правило хартии из паузы выключают режим немедленно.

## 4. Режим, архив, обёртка, документация
- [x] 4.1 Тест: промежуточный отчёт сохраняет режим, ставит `awaiting_child`, отправляет ровно одно продолжение с id родителя; без нового действия агента новых продолжений нет, включая механизм простоя; финальный отчёт кампании, после которой цепочка не может продолжаться, выключает режим (дельта research-vectors).
- [x] 4.2 Тест: кампания активной цепочки не архивируется при draft дочернего брифа; сторонние stopped-кампании архивируются; вне цепочки архивация по общим правилам (дельта research-vectors).
- [x] 4.3 Тест: кампания цепочки в фазе research (цепочка остановлена во время работы) — финальный отчёт выключает режим, исключение «Отчёт незавершённой кампании» действует только вне цепочек (дельта research-vectors).
- [x] 4.4 Тест: обёртка `scripts/research-rpc.mjs` — `--charter` без `--approve-charter-sha` (и наоборот) — ошибка разбора до запуска pi; отдельная регулярка `Charter SHA-256:` (префикс не пересекается с `Brief SHA-256:`); несовпадение → ответ `false` и код выхода 3 без состояния; корневой бриф подтверждается как сейчас; системные id кампаний `<chain-id>-c<номер>`. Реализация: флаги, регулярка, диалог, назначение id, ожидание после промежуточного отчёта.

- [x] 4.6 Тест: без `--charter` поведение обёртки прежнее; коды выхода существующих сценариев не меняются.
- [x] 4.7 Тест: git-команда в кампании цепочки отклоняется по правилам `research-vectors` (требование «Без git и без расширения возможностей кампании»).
