# Tasks: research-charter

Ревизия: rev.2. Тесты пишутся до кода. Каждый пункт 1.x–5.x — с тестом, который падает на текущем коде (если пункт не помечен как документация).

## 1. Хартия и согласование
- [ ] 1.1 Тест: хартия без ожидаемого хеша не принимается; модель не может передать одобрение (allowlist параметров: любые неизвестные поля отклоняются).
- [ ] 1.2 Тест: realpath пути хартии внутри рабочего каталога отказывает (`charter_inside_workdir`), включая symlink/junction и регистр имён Windows.
- [ ] 1.3 Тест: интерактивный диалог начинается с `Charter SHA-256: <hex>`, показывает лимиты и стоп-правила; при `ctx.hasUI = false` отклоняется; отказ владельца не фиксирует хартию.
- [ ] 1.4 Реализация: загрузка хартии, вычисление и сверка хеша; пере-хеширование в момент подтверждения (файл изменился между показом и подтверждением → подтверждение не фиксируется); диалог подтверждения (строго `true`).
- [ ] 1.5 Тест и реализация: состав хартии, действующие значения по умолчанию (5 кампаний, глубина 4, корень = 0), отказ при правилах смены вердиктов или `evidence_gate`; линейность цепочки (у кампании не более одного потомка).

## 2. Автоподтверждение брифов цепочки
- [ ] 2.1 Тест: бриф, проходящий проверки, подтверждается автоматически; `approval.json` записан системой с источником `charter` и хешем хартии; решение записано в `chain.json` с хешем брифа, хешем хартии и снимком родителя.
- [ ] 2.2 Тест: вопрос без ссылки на находку цепочки (`finding_missing`) и со ссылкой на несуществующую пару `campaign_id` + `question_id`.
- [ ] 2.3 Тест: смена блока ограничений (`caveat_changed`); расхождение эффективного набора вердиктов или `evidence_gate` (`verdicts_or_gate_changed`); бриф не проходит схему; родитель без `verdicts` + потомок с явным тем же набором — совпадение.
- [ ] 2.4 Тест: превышение лимита кампаний и лимита глубины (корень = 0) → `limit_reached`; повторная отправка подтверждённого брифа не создаёт вторую кампанию.
- [ ] 2.5 Реализация проверок брифа цепочки поверх существующей валидации `research_brief draft`; модификация «Подтверждение только пользователем» (исключение для цепочки).

## 3. Журнал, статусы, остановка, ручная проверка
- [ ] 3.1 Тест: append-only журнал с `prev_hash`-цепочкой; повтор не переписывает предыдущие записи; головной хеш сверяется при каждом действии.
- [ ] 3.2 Тест: расхождение хеш-цепочки, повреждённый и отсутствующий `chain.json` → `manual_check_required`.
- [ ] 3.3 Реализация статусов цепочки (`active`, `awaiting_child`, `limit_reached`, `stopped_by_owner`, `stopped_by_rule`, `manual_check_required`, `completed`): начальный статус, финальные статусы, отказ действий при финальном статусе; журнал в `<state-root>/research-chain/<id>/` вне каталогов кампаний.
- [ ] 3.4 Тест и реализация `research chain_stop`: диалог оператора строго `true` (модель без подтверждения отклоняется), статус `stopped_by_owner`, новые брифы отказывают, открытый вектор не прерывается, режим не выключается до финального отчёта.
- [ ] 3.5 Тест: стоп-правило хартии (самоотчёт агента) → `stopped_by_rule`.

## 4. Режим, архив, обёртка, документация
- [ ] 4.1 Тест: промежуточный отчёт сохраняет режим, ставит `awaiting_child`, отправляет ровно одно продолжение; без нового действия агента новых продолжений нет, включая механизм простоя; отчёт, после которого цепочка не может продолжаться, выключает режим (дельта research-vectors).
- [ ] 4.2 Тест: кампания активной цепочки не архивируется при draft дочернего брифа; вне цепочки архивация по общим правилам (дельта research-vectors).
- [ ] 4.3 Реализация обёртки `scripts/research-rpc.mjs`: `--charter`, `--approve-charter-sha` (hex 64 нижний регистр), отдельная регулярка `Charter SHA-256:`, ответ `true` только при совпадении; несовпадение/отказ → код выхода 3 без создания состояния; промежуточный отчёт цепочки не завершает сеанс — продолжение доставляется и сеанс ждёт; корневой бриф подтверждается как сейчас; системные id кампаний `<chain-id>-c<номер>`.
- [ ] 4.4 Тест: без `--charter` поведение обёртки прежнее; коды выхода существующих сценариев не меняются.
- [ ] 4.5 Обновить `docs/research-vectors.md` (раздел про цепочку).
