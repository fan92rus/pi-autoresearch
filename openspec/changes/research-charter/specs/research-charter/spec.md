# research-charter Specification

## Purpose
Владелец один раз согласовывает рамки, в которых агент сам ведёт цепочку исследовательских кампаний: следующий бриф строится из находок предыдущей кампании и подтверждается по рамкам, без диалога на каждом шаге. По решению владельца цепочка по умолчанию без лимитов; лимиты — опциональные поля хартии.

## ADDED Requirements

### Requirement: Хартия подтверждается владельцем
Система SHALL начинать цепочку только при хартии, подтверждённой владельцем. В headless-режиме ожидаемый хеш хартии MUST задаваться владельцем аргументом запуска. В интерактивной сессии модель MAY передать только путь хартии; ожидаемый хеш владелец не передаёт: система MUST вычислить SHA-256 файла самостоятельно. Модель MUST NOT передавать ожидаемый хеш, подтверждение или поля одобрения; вызов с любым неизвестным действию полем MUST отклоняться (allowlist параметров). Диалог подтверждения MUST начинаться строкой `Charter SHA-256: <hex>`, MUST показывать поля хартии и приниматься только как строго `true`. Система MUST пере-вычислить хеш файла в момент подтверждения и MUST NOT фиксировать подтверждение, если файл изменился после показа. Канал диалога headless-обёртки считается интерфейсом владельца.

#### Scenario: Подтверждение диалогом
- **WHEN** владелец в интерактивной сессии подтверждает диалог, первая строка которого `Charter SHA-256: <hex>` с полями хартии, и файл с момента показа не менялся
- **THEN** хартия фиксируется с этим SHA-256, цепочка может начаться

#### Scenario: Владелец отказал в диалоге
- **WHEN** диалог подтверждения хартии вернул не `true`
- **THEN** хартия не фиксируется, состояние цепочки не создаётся

#### Scenario: Подтверждение аргументом запуска
- **WHEN** headless-запуск передан с `--charter` и `--approve-charter-sha`, и хеш файла хартии совпадает
- **THEN** хартия принимается без интерактивного диалога

#### Scenario: Модель передаёт одобрение
- **WHEN** в вызове инструмента присутствуют поля `approved`, `confirmed`, `charter_sha256`, `operator_confirmation` или любое поле вне allowlist действия
- **THEN** вызов отклоняется, хартия не фиксируется

#### Scenario: Хеш не совпадает
- **WHEN** файл хартии не совпадает с ожидаемым хешем или изменился между показом и подтверждением
- **THEN** цепочка не начинается, состояние не создаётся

#### Scenario: Нет интерфейса
- **WHEN** интерактивное подтверждение запрошено при `ctx.hasUI = false`
- **THEN** подтверждение отклоняется, состояние цепочки не создаётся

### Requirement: Хартия вне рабочей директории агента
Система MUST NOT принимать хартию, realpath которой лежит внутри рабочего каталога запуска (с учётом symlink/junction и регистра имён Windows). Хеш из аргументов запуска или пересчитанный в момент диалога является источником истины; файл хартии без совпадения с ним не имеет силы.

#### Scenario: Хартия внутри рабочей директории
- **WHEN** realpath пути хартии ведёт внутрь рабочего каталога, в том числе через symlink или junction
- **THEN** запуск отказывает с причиной `charter_inside_workdir`

#### Scenario: Хартия изменена после подтверждения
- **WHEN** содержимое файла хартии отличается от подтверждённого хеша в любой момент цепочки
- **THEN** каждое действие цепочки отказывает с `charter_changed`, и цепочка переходит в `manual_check_required`

### Requirement: Состав хартии
Хартия — JSON-объект с полями: необязательные `max_campaigns` (целое ≥ 1, максимум кампаний цепочки, включая корневую) и `max_depth` (целое ≥ 0, максимум глубины кампании от корневой, корневая имеет глубину 0); при линейной цепочке глубина = число кампаний − 1, поэтому поля эквивалентны и действуют одновременно, если заданы оба; без них лимитов нет и цепочка неограниченная. Необязательный массив строк `stop_rules` — стоп-правила цепочки. Хартия MUST NOT содержать полей вне этого набора (allowlist) и MUST NOT содержать правил, разрешающих изменение эффективного набора вердиктов, `evidence_gate` или блока ограничений цепочки.

#### Scenario: Хартия без лимитов
- **WHEN** в хартии нет `max_campaigns` и `max_depth`
- **THEN** цепочка не ограничена числом кампаний и глубиной

#### Scenario: Лимиты заданы
- **WHEN** хартия задаёт `max_campaigns` и/или `max_depth`
- **THEN** соответствующий лимит применяется по правилам требования «Автоподтверждение брифа цепочки»

#### Scenario: Хартия разрешает смену вердиктов
- **WHEN** хартия содержит правило, меняющее эффективный набор вердиктов, `evidence_gate` или блок ограничений
- **THEN** хартия не принимается, цепочка не начинается

#### Scenario: Хартия с неизвестным полем
- **WHEN** хартия содержит поле вне allowlist
- **THEN** хартия не принимается, цепочка не начинается

### Requirement: Автоподтверждение брифа цепочки
Система SHALL подтверждать бриф следующей кампании цепочки без диалога только если бриф проходит все проверки: схема брифа; блок ограничений дословно равен родительскому; **эффективный** набор вердиктов равен родительскому — родитель без поля `verdicts` и потомок с явно объявленным тем же набором совпадают (семантика поля — research-brief-gates); объект `evidence_gate` равен родительскому, где массивы сравниваются как множества без учёта порядка, отсутствие у обоих — совпадение; каждый вопрос брифа несёт поле `finding_refs` — непустой массив пар `{campaign, question}`, и каждая пара указывает на вопрос, закрытый с доказательством в кампании с таким идентификатором этой цепочки (источник проверки — журналы кампаний цепочки: событие `close` с вердиктом из эффективного набора той кампании и записанным доказательством); лимиты хартии, если заданы, не превышены: число кампаний включая корневую и глубина (корень = 0). Подтверждённым считается только бриф, ещё не подтверждённый ранее: повторная отправка того же брифа MUST NOT создавать вторую кампанию. Автоподтверждение ДОЛЖНО выполняться только при статусе цепочки `awaiting_child` (промежуточный отчёт родителя записан): бриф, отправленный до отчёта родителя, MUST отклоняться с причиной `parent_not_reported` без записи в журнал лимитов. Каждое подтверждение записывается в журнал цепочки (см. «Журнал цепочки»).

#### Scenario: Бриф проходит проверки
- **WHEN** агент отправляет бриф следующей кампании, который проходит все проверки
- **THEN** бриф подтверждается автоматически, кампания создаётся, решение записано в журнал

#### Scenario: Вопрос без находки цепочки
- **WHEN** у вопроса нет `finding_refs`, массив пуст, или пара `{campaign, question}` не указывает на закрытый с доказательством вопрос кампании цепочки
- **THEN** бриф отклоняется с причиной `finding_missing`, кампания не создаётся, причина записана в журнал

#### Scenario: Расхождение набора вердиктов или evidence_gate
- **WHEN** эффективный набор вердиктов или объект `evidence_gate` брифа отличается от родительского
- **THEN** бриф отклоняется с причиной `verdicts_or_gate_changed`, кампания не создаётся, причина записана в журнал

#### Scenario: Бриф до отчёта родителя
- **WHEN** агент отправляет бриф следующей кампании при статусе `active` (промежуточный отчёт родителя ещё не записан)
- **THEN** бриф отклоняется с причиной `parent_not_reported`, кампания не создаётся

#### Scenario: Бриф не проходит схему
- **WHEN** бриф не проходит стандартную схему research_brief
- **THEN** бриф отклоняется со стандартной причиной схемы, автоподтверждение не выполняется

#### Scenario: Повторная отправка подтверждённого брифа
- **WHEN** агент повторно отправляет бриф с хешем уже подтверждённого брифа цепочки
- **THEN** вторая кампания не создаётся, система возвращает запись журнала о первом подтверждении

#### Scenario: Смена блока ограничений
- **WHEN** блок ограничений в брифе отличается от родительского
- **THEN** бриф отклоняется с причиной `caveat_changed`

#### Scenario: Превышение лимита
- **WHEN** лимиты заданы и отправленный бриф следующей кампании превысил бы лимит числа кампаний или лимит глубины (корень = 0)
- **THEN** бриф отклоняется, цепочка переходит в статус `limit_reached`

#### Scenario: Отчёт последней разрешённой кампании при лимитах
- **WHEN** лимиты заданы и записан отчёт кампании, достигшей лимита (следующая кампания превысила бы лимит)
- **THEN** статус цепочки `limit_reached`, режим выключается этим отчётом; отправка следующего брифа отказывает как действие финального статуса

#### Scenario: Лимиты не заданы
- **WHEN** лимитов в хартии нет и агент отправляет корректный следующий бриф на любую глубину
- **THEN** проверки лимитов пропускаются, бриф проходит автоподтверждение на общих основаниях

### Requirement: Журнал цепочки
Система SHALL вести журнал цепочки `chain.json` в каталоге цепочки `<state-root>/research-chain/<id>/` — вне каталогов кампаний: идентификатор цепочки, корневая кампания, список кампаний с родителем и глубиной, решения об автоподтверждении и отказах. Запись подтверждения содержит: хеш брифа, хеш хартии, снимок сопоставляемых полей родительского брифа (`caveat_block`, эффективный набор вердиктов, `evidence_gate`, идентификатор кампании). Запись отказа содержит именованную причину и хеш брифа. Каждая запись несёт `prev_hash` предыдущей записи; головной хеш хранится в отдельном файле `chain-head` того же каталога и сверяется при каждом действии цепочки; источником проверок ссылок на находки служат журналы кампаний, а не копии в `chain.json`. Журнал MUST быть append-only: записи не переписываются и не удаляются.

#### Scenario: Отказ записан
- **WHEN** бриф отклонён проверкой хартии
- **THEN** в журнале есть запись об отказе с именованной причиной и хешем брифа

#### Scenario: Журнал не переписывается
- **WHEN** цепочка продолжается после отказа
- **THEN** предыдущие записи журнала остаются без изменений

#### Scenario: Повреждение или отсутствие журнала
- **WHEN** сверка головного хеша не сходится, `chain.json` или `chain-head` не читается или отсутствует при действии цепочки
- **THEN** действия цепочки отказывают, статус `manual_check_required`

### Requirement: Статусы цепочки
Цепочка SHALL иметь ровно один статус: `active` (начальный; идёт кампания цепочки), `awaiting_child` (промежуточный отчёт записан, ожидается бриф следующей кампании), `limit_reached` (только при заданных лимитах), `stopped_by_owner`, `stopped_by_rule`, `manual_check_required`, `completed` (отчёт кампании, после которой цепочка не может продолжаться, записан). Финальные статусы, при которых создание кампаний и действия цепочки отказывают: `limit_reached`, `stopped_by_owner`, `stopped_by_rule`, `manual_check_required`, `completed`; исключение — `report` активной кампании после остановки во время её работы (см. «Режим исследования в цепочке»). Предикат «цепочка может продолжаться»: статус `active` или `awaiting_child`, хартия подтверждена и её хеш совпадает, лимиты не заданы либо следующая кампания не превысит ни один из них. Статус `limit_reached` устанавливается отклонённым брифом, превысившим лимит, либо отчётом кампании, достигшей лимита; при безлимитной цепочке этот статус не достижим. Долговременная пауза `awaiting_child` — заявленный остаточный риск: режим остаётся включённым без новых продолжений, пока владелец не вызовет `chain_stop` или агент не выполнит новое действие.

#### Scenario: Начальный статус
- **WHEN** хартия подтверждена и корневая кампания стартовала
- **THEN** статус цепочки `active`

### Requirement: Остановка цепочки
Система MUST прекращать создание новых кампаний цепочки при любом из условий: сработало стоп-правило хартии (самоотчёт агента, заявленный остаточный риск); владелец вызвал остановку командой `research chain_stop` (диалог оператора; модель MUST NOT подтверждать за владельца); лимит, если задан; цепочка в `manual_check_required`; файл хартии изменился. Остановка не удаляет и не переносит уже созданные кампании и не прерывает работу открытого вектора активной кампании. Из `awaiting_child` выход к продолжению цепочки — только новое действие агента (бриф); `chain_stop` из `awaiting_child` переводит цепочку в `stopped_by_owner` и выключает режим немедленно.

#### Scenario: Владелец останавливает цепочку в паузе
- **WHEN** владелец подтверждает диалог `research chain_stop` при статусе `awaiting_child`
- **THEN** статус цепочки `stopped_by_owner`, режим исследования выключается немедленно, новые брифы цепочки отказывают

#### Scenario: Владелец останавливает цепочку во время кампании
- **WHEN** владелец подтверждает `research chain_stop` при статусе `active`
- **THEN** статус `stopped_by_owner`, новые брифы цепочки отказывают; открытый вектор не прерывается; активная кампания завершает работу по правилам `research-vectors` и пишет финальный отчёт, который выключает режим

#### Scenario: Модель пытается остановить цепочку
- **WHEN** модель вызывает `chain_stop` без подтверждения оператора в диалоге
- **THEN** вызов отклоняется, статус не меняется

#### Scenario: Стоп-правило хартии во время кампании
- **WHEN** условие стоп-правила хартии выполнено при статусе `active` и агент это отмечает
- **THEN** статус цепочки `stopped_by_rule`, новые кампании не создаются, активная кампания завершает финальный отчёт по правилам режима

#### Scenario: Стоп-правило хартии в паузе
- **WHEN** условие стоп-правила хартии выполнено при статусе `awaiting_child` и агент это отмечает
- **THEN** статус цепочки `stopped_by_rule`, режим исследования выключается немедленно (отчёт последней кампании уже сохранён)

#### Scenario: Ручная проверка
- **WHEN** обнаружено расхождение хеша хартии или головного хеша журнала, журнал повреждён или отсутствует
- **THEN** статус цепочки `manual_check_required`, действия цепочки отказывают до ручного разбора

### Requirement: Режим исследования в цепочке
Система SHALL сохранять режим исследования включённым между кампаниями цепочки. Режим исследования выключается отчётом кампании, после которого «цепочка может продолжаться» ложно, после того как `report.md` сохранён; для остановленной во время работы цепочки финальный отчёт её активной кампании выключает режим независимо от фазы кампании — это явное исключение из правила «Отчёт незавершённой кампании режим не меняет» (то правило действует вне цепочек). `chain_stop` или стоп-правило хартии при статусе `awaiting_child` выключают режим немедленно. После промежуточного отчёта система SHALL отправить агенту одно продолжение, которое направляет его к брифу следующей кампании и несёт идентификатор кампании-родителя. Повторного продолжения без нового действия агента система MUST NOT отправлять; в статусе `awaiting_child` механизм простоя MUST NOT присылать новых продолжений.

#### Scenario: Промежуточный отчёт
- **WHEN** отчёт кампании цепочки сохранён, кампания в фазе `stopped` и «цепочка может продолжаться» истинно
- **THEN** режим остаётся включённым, статус цепочки `awaiting_child`, агенту отправлено одно продолжение с указанием написать бриф следующей кампании и идентификатором родителя

#### Scenario: Отчёт в фазе research не продвигает цепочку
- **WHEN** отчёт кампании цепочки записан, а кампания остаётся в фазе `research` (не остановлена)
- **THEN** статус цепочки остаётся `active`, продолжение не отправляется, режим остаётся включённым; ответ агенту сообщает, что цепочка продвигается только после остановки кампании и отчёта

#### Scenario: Агент не написал следующий бриф
- **WHEN** после продолжения агент завершил ход без нового брифа
- **THEN** повторного продолжения нет, включая автопродолжения простоя; статус цепочки остаётся `awaiting_child` до нового действия агента или `chain_stop`

#### Scenario: Финальный отчёт последней кампании
- **WHEN** сохранён отчёт кампании, после которой «цепочка может продолжаться» ложно, и `report.md` записан
- **THEN** режим выключается по правилу `research-vectors`, статус цепочки `completed` (или соответствующий финальный статус, если остановка уже была записана)

#### Scenario: Финальный отчёт остановленной во время работы цепочки
- **WHEN** цепочка остановлена при статусе `active`, активная кампания завершила векторы и записала `report.md` в фазе `research`
- **THEN** режим выключается этим отчётом как явное исключение из правила «Отчёт незавершённой кампании режим не меняет»

### Requirement: Без git и без расширения возможностей кампании
Кампании цепочки SHALL соблюдать все требования `research-vectors`: без git-операций, с неизменяемым брифом каждой кампании, с закрытием вопросов только по правилам брифа с доказательством и с ручной проверкой при сбоях. Цепочка MUST NOT давать агенту возможностей вне кампании, кроме автоподтверждения брифов, прошедших проверки хартии, и назначенных системой продолжений к ним.

#### Scenario: Кампания цепочки пытается коммитить
- **WHEN** агент в кампании цепочки вызывает git-команду
- **THEN** команда отклоняется по правилам `research-vectors`

### Requirement: Headless-запуск цепочки
Обёртка `scripts/research-rpc.mjs` SHALL принимать `--charter <путь>` и `--approve-charter-sha <hex 64 символа в нижнем регистре>`; аргументы взаимно обязательны: отсутствие любого из них — ошибка разбора до запуска pi, без создания состояния. Диалог `Charter SHA-256:` обёртка MUST распознавать отдельной регуляркой (префикс не пересекается с `Brief SHA-256:`) и отвечать `true` только при совпадении с `--approve-charter-sha`; при несовпадении — ответ `false` и код выхода 3, состояние не создаётся. Корневой бриф подтверждается как сейчас (`--brief` + `--approve-sha`); последующие брифы цепочки автоподтверждаются по хартии. Промежуточный отчёт цепочки MUST NOT завершать запуск: обёртка доставляет продолжение и ждёт следующего действия агента; если агент завершил ход в статусе `awaiting_child`, обёртка завершается штатно с кодом 0, состояние сохраняется. Идентификаторы кампаний цепочки назначает система (`<chain-id>-c<номер>`); агент не передаёт их. Коды выхода существующих сценариев не меняются. Для запуска без хартии поведение остаётся прежним, включая требование `--approve-sha` для каждого брифа.

#### Scenario: Запуск с хартией
- **WHEN** обёртка запущена с `--charter`, совпадающим `--approve-charter-sha`, `--brief` и `--approve-sha`, диалог хартии распознан и отвечен `true`
- **THEN** цепочка стартует; корневой бриф подтверждается как сейчас; последующие брифы цепочки автоподтверждаются по хартии; промежуточный отчёт не завершает сеанс

#### Scenario: Отказ хартии в headless
- **WHEN** хеш хартии не совпал или диалог хартии ответил не `true`
- **THEN** ответ диалога `false`, запуск завершается с кодом выхода 3, состояние цепочки не создаётся

#### Scenario: Пауза цепочки в headless
- **WHEN** агент завершил ход в статусе `awaiting_child` (без нового брифа)
- **THEN** обёртка завершается с кодом 0, состояние цепочки сохраняется на диске

#### Scenario: Отсутствие обязательного аргумента
- **WHEN** `--charter` передан без `--approve-charter-sha` (или наоборот)
- **THEN** ошибка разбора аргументов до запуска pi, состояние не создаётся

#### Scenario: Запуск без хартии
- **WHEN** обёртка запущена без `--charter`
- **THEN** поведение совпадает с текущим, каждый бриф требует своего `--approve-sha`
