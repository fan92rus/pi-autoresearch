# Промпты и skills для кандидатного MVP

Включено по прямому запросу владельца; применимо вместе с MVP `design.md` rev.5. Эта редакция не требует marker/registry или автоматического recovery из прежнего draft.

## Требования

1. Инвентаризировать и обновить реально используемые инструкции: `skills/autoresearch-*`, шаблон `.auto/prompt.md`, startup/resume/compaction и observer/council steers, tool descriptions и сообщения о блокировке benchmark в `extensions/pi-autoresearch/`. Источники и проверки перечислить в документации реализации.
2. Для активного режима описать цикл `candidate_branch`, раздельные worktree и leader ref, сохранение checkpoint, порог и подтверждение policy пользователем. Обычные `run_experiment`/`log_experiment` с auto-revert не должны предписываться внутри этого режима. Общая инструкция автономности не отменяет согласия человека.
3. Для отключённого режима сохранить прежние инструкции и поведение. После незавершённой операции не подталкивать агента к новому измерению или автоматической очистке — показать остановку и ручную проверку.
4. Существующий пользовательский `.auto/prompt.md` не перезаписывать. Для новых кампаний шаблон учитывает выбранный режим.
5. Не предлагать отключённые phases, SpaceSearch и другие скрытые инструменты как доступные; не включать их лишь ради документации. Последовательные кандидаты не называются параллельным поиском.

## Проверки

Тестировать сформированные инструкции для обоих режимов, resume после сбоя, согласование policy, сохранность существующего prompt и соответствие примеров фактическому зарегистрированному API. Для активного режима проверить отсутствие конфликтующих инструкций обычного цикла; для обычного — отсутствие регрессии legacy-инструкций.
