## Phase 2: Measurement-трек

- [ ] 2.1 Tool `log_measurement_change`: валидация diff_ref (файл существует) и rescore_ref (воспроизводимый рескор-артефакт: якорный набор, команды, обе оценки; числа парсятся из артефакта), justification (finding id или причина), запись `measurement_change` с epoch+1 и `needs_verification: true`; диффы и рескор-артефакты в `.auto/measurement/`; тесты: корректная запись, отказ без диффа или артефакта, pending с артефактом без оценок, числа извлечены из полного артефакта
- [ ] 2.2 Эпохи в леджере: `epoch` в parse/reconstruct (jsonl.ts), записи без epoch = эпоха 1; тесты обратной совместимости старых логов
- [ ] 2.3 Блокировка поперечных сравнений: confidence score и best-дельты не вычисляются поперёк эпох (пометка cross-epoch, обе шкалы), dashboard/tree разделяют эпохи; тесты: сравнение внутри эпохи работает, поперёк — блокировано
- [ ] 2.4 Учёт обеих шкал: old/new_scale_score парсятся из рескор-артефакта, rescore_pending и предварительная шкала до верификации, подавление confidence при rescore_pending; тесты: обе шкалы из артефакта, отложенный рескор, предварительная шкала в дашборде
- [ ] 2.5 Переоценка floor: после measurement_change floor помечен устаревшим, keep без свежего floor сохраняется с пометкой, confidence подавляется; тесты: keep до/после переоценки
- [ ] 2.6 Measurement-EXP в validateSlate: формат `TRACK: measurement` (строка в секции) + план DIFF/RESCORE/JUSTIFY вместо числового EXPECTED_GAIN; синхронная правка инструкций chair (шаблон EXP в инструкциях chair и проверка slate в основном цикле) и challenge-брифов; тесты: measurement-EXP с полным планом принят, с неполным — отклонён с именем недостающего поля, model-EXP без числа отклонён
- [ ] 2.7 Loop-промпт и контроль объявленных файлов измерителя: манифест содержит их хеши; observer и бриф предупреждают о неучтённом изменении, а при отсутствии объявления — об ограничении контроля; тесты изменения хеша, отсутствия объявления и недоступного объявленного файла.
- [ ] 2.8 Верификация measurement_change: независимая проверка рескор-артефакта (challenge-фаза или повторное чтение), снятие needs_verification и предварительной метки; ветка опровержения (контр-рескор, откат шкалы к верифицированному состоянию); тесты: дополняющая запись подтверждения без перезаписи, measurement_change_completed с обеими оценками без новой эпохи и файл доказательства верификации, компенсирующая запись при опровержении, несравнимость отклонённых прогонов, восстановление активной шкалы и монотонность идентификаторов эпох
