# Amendment: подталкивание к заведению векторов по находкам (state-aware nudge)

**Родительская спека:** `openspec/changes/research-expedition` (реализована, 8.3 ревью в процессе)
**Тип:** amendment (новое поведение поверх реализованной экспедиции)
**Статус:** черновик — цикл документного ревью по `plan-loop` после одобрения владельцем
**Бд:** pi-autoresearch (задача на амендмент будет заведена при одобрении)

## Why

Экспедиция даёт агенту карту и инструменты, но направление движения агент выбирает имплицитно:
после закрытия вектора (`resolve`/`reject`/`advisory`/`park`) reply «map recorded» не предлагает
следующего шага — агент встаёт или действует по привычке («активируй следующий по очереди»), не
перерабатывая находки закрытого вектора в новые гипотезы. Живой кейс 2026-11-12: 6 направлений
opened, 0 activated, экспедиция стояла; также агент предлагал завершение кампании после каждого
этапа (преждевременный stop). Нужен механический протокол «что делать с результатами».

## Решение владельца (2026-11-12, чат, дословная семантика)

1. После закрытия текущего вектора — подталкивать агента **по результатам заводить новые
   векторы**, или честно не заводить.
2. **Новый вектор — опция, не требование**: если находки гипотезы не дают, это валидный исход.
3. **Завершение кампании — только при исчерпании**: все вопросы брифа закрыты **И** новых
   векторов не наблюдается. После отдельного этапа кампанию не закрывать.
4. **Двухшаговый протокол**: ШАГ 1 — заводить новые векторы из находок (можно несколько подряд,
   пока находки дают гипотезы); ШАГ 2 — отдельным осознанным шагом выбрать, какой из накопившихся
   open-векторов приоритетнее активировать. Активация «следующего по очереди» — не парное
   действие к заводке.

## What Changes

- **ADDED** state-aware nudge в reply после `expedition_map subaction=resolve|reject|advisory|park`
  (только экспедиционная цепочка, только кампания в фазе `research`; не-экспедиция и прочие фазы —
  reply бит-в-бит прежний):
  - есть находки, дающие гипотезы → «заведи новые векторы: `expedition_map(subaction=open,
    dir=<имя>, why=<finding>)`, можно несколько подряд; активация — отдельным следующим шагом»;
  - находок-гипотез нет, но есть `open`-направления → «выбери приоритетный open и активируй:
    `subaction=activate, dir=<имя>, why=<rationale>`; новые векторы заводить не обязательно»;
  - находок нет, `open` нет, но есть reopenable (`parked`/`advisory_exhausted`/`resolved`/
    `rejected`) → «если находки обосновывают reopen: `subaction=reopen`; иначе продолжай работу
    кампании / готовь следующий бриф»;
  - **ветка исчерпания** (все вопросы брифа закрыты И нет `open` И находки не дают гипотез):
    «территория исчерпана: закрой кампанию `research_questions(action=stop, rule_id=<stop-правило
    брифа>)` → `action=report`; цепь перейдёт в `awaiting_child`».
- **ADDED** steer-продолжение (`sendWhenReady(..., {steerIfBusy:true})`), когда закрыт последний
  `active` и `open` нет, кампания в `research`: агент мог закончить ход на tool-reply — steer
  продолжает ход с тем же nudge. Семантика «один steer на событие закрытия» — по
  построению один send на вызов, once-per-chain флаг удалён (ревью 2026-11-12).
- **ADDED** map-подсказка в `closingNudge` после закрытия **всех** вопросов кампании экспедиционной
  цепочки: «закрой направление отдельным вызовом `expedition_map(subaction=resolve|reject|
  advisory|park, ...)` — close вопроса ≠ resolve направления».
- **ADDED** перечень незакрытых направлений в финальном reply при остановке экспедиции при живых
  незакрытых направлениях: перечень со статусами + «новая экспедиция по ним: `expedition_brief
  draft`» (незакрытые направления в отчёте — существующая секция «Unfinished»). При 0 — ничего.

## Constraints (уроки ревью)

- Тексты nudge на английском (стиль соседних reply), валидные формы вызовов по контрактам
  `expedition_map`/`research_questions` (см. спеку research-tool-aliases).
- Формулировки — решение, не давление: «если находки дают гипотезу — заводи; если нет — это
  валидный исход». Никакого императива открытия.
- nudge после отдельного этапа НЕ содержит stop; stop появляется только в ветке исчерпания
  (все вопросы закрыты + кандидатов нет).
- Не-экспедиционные цепочки: регресс бит-в-бит.

## Tasks (черновик)

1. Красные тесты: 4 ветки nudge (находки/open/reopenable/исчерпание), steer после последнего
   active, map-подсказка в closingNudge, финальный перечень незакрытых, регресс не-экспедиции.
2. Реализация в `index.ts` (replay после перехода, обогащение reply, steer-флаг).
3. Регресс-трио + полный serial, openspec validate --all.
4. Документное ревью амендмента свежим агентом до ГОДЕН (plan-loop), затем реализация.
