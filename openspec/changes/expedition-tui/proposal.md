# Proposal: expedition-tui — экспедиция на всех TUI-поверхностях

## Why

Владелец экспедиции видит ход исследования только в узком виджете (10-11 строк) и в финальном
`expedition-report.md`. Все остальные TUI-поверхности расширения либо игнорируют экспедицию,
либо показывают её обеднённо:

| Поверхность | Сейчас | Проблема |
|---|---|---|
| Виджет `autoresearch` | карта направлений + счётчик `Q 2/5` | вердикты закрытых вопросов не видны: `Q1 confirmed, Q2-Q5 rejected` — главное «достижение/неудача» — скрыто за числом |
| `/autoresearch dashboard` (fullscreen overlay) | только для обычного цикла: в экспедиции `state.results.length === 0` → «No experiments yet» | главный информационный экран недоступен экспедиции вовсе |
| Транскрипт тулов | `research`/`research expedition` рисуются серым заголовком | история действий агента (`activate`, `resolve` с обоснованиями) нечитаема в скролле |
| `/autoresearch web` (браузер) | читает только ledger обычного цикла (`.auto/log.jsonl`) | в expedition-проекте открывает пустой/ошибочный дашборд |

«Не вижу достижений в UI» (владелец, 2026-11-12) — прямой симптом: данные есть (6 направлений,
5 вердиктов, evidence-файлы), поверхностей, где это показано, — одна, и та узкая.

## What Changes

**Bump: new capability `research-expedition-tui` + 2 ADDED-requirement к существующей
`research-expedition`** (виджет: вердикты; fullscreen: ветвление точки входа).

1. **Fullscreen expedition view** — `/autoresearch dashboard` при активной экспедиции открывает
   overlay с картой целиком: направления (глиф, имя, основание, refs, кампания), таймлайн
   решений с обоснованиями, вопросы активной кампании с вердиктами и evidence, счётчики.
   Прокрутка и клавиши — как у существующего overlay обычного цикла.
2. **renderCall для expedition-действий `research`** — строки тулов в транскрипте рисуют действие
   человеческим языком (`🔄 activate «Seed-ensemble» — усреднение…`) вместо серого заголовка;
   не-expedition-действия `research` визуально не меняются.
3. **Web-дашборд экспедиции** — `/autoresearch web` при активной экспедиции генерирует страницу
   с картой + таймлайном (read-only); страница обновляет данные через существующий SSE-сигнал
   `jsonl-updated` плюс периодический опрос маршрута `/expedition` (JSON view; новых broadcast-точек не
   добавляется); headless-вызов получает ЯВНЫЙ отказ — НОВОЕ поведение, которого сейчас нет
   (сейчас exportDashboard работает без UI-гейта); вне экспедиции — прежний ledger-дашборд
   без изменений, включая текущее отсутствие headless-гейта (его изменение — out of scope).
4. **Вердикты закрытых вопросов в виджете** — одна строка `Q: Q1 ✓ Q2 ✗ …` с вердиктами последней
   кампании рядом с существующим счётчиком.

## Capabilities

### New: `research-expedition-tui` (3 требования, 18 сценариев)
- Fullscreen expedition view (требование + 6 сценариев: активная экспедиция, повреждённый журнал,
  обычный цикл без экспедиции, обычный цикл пустой, headless, длинный таймлайн).
- Транскрипт expedition-действий (требование + 5 сценариев: активация, закрытие с refs, pivot,
  не-expedition регресс, битые args).
- Web-дашборд экспедиции (требование + 7 сценариев: экспедиция активна, вне экспедиции — регресс,
  headless в экспедиции, повреждённый журнал, повторный вызов тот же workDir, повторный вызов
  другой workDir, живое обновление).
- Уточнение контрактов (ревью R1): web-обновление — маршрут `/expedition` (JSON view) по
  SSE-сигналу `jsonl-updated` И по таймеру 10с; broadcast-точки для экспедиционных файлов НЕ
  добавляются; headless-гейт ТОЛЬКО в expedition-ветке, не-expedition путь остаётся как есть.

### ADDED (отдельное требование, не MODIFIED): `research-expedition`
- Вердикты в виджете — отдельное ADDED-требование «Вердикты вопросов в виджете карты» (3 сценария:
  есть закрытые — строка есть, нет закрытых — строки нет, неизвестный вердикт — глиф `*`) рядом с
  существующим «Виджет карты» (не MODIFIED): существующий контракт футера не переписывается,
  строка вердиктов добавляется рядом со счётчиком `Q n/m`. Каноническое место требования — delta
  capability `research-expedition`; в новой capability оно НЕ дублируется.

## Out of Scope

- Tab-переключение виджет-режимов (карта ↔ таймлайн) — отложено владельцем («остальное потом»).
- Акцент «waiting: бриф следующей кампании» в виджете — отложено.
- Валидация hash-цепочки в TUI-рендерах — не добавляется (read-only отображение, как у виджета).
- Экспорт expedition-карты в файл (кроме существующего report.md) — не делается.
- Изменения семантики карты/переходов/предиката — только отображение.
- Введение UI-гейта для web-команды ВНЕ экспедиции (сейчас headless работает) — сохраняем
  как есть; гейт добавляется только в expedition-ветке.
