# expedition-tui — Delta Specs

## ADDED Requirements

### Requirement: Fullscreen-карта экспедиции

При активной экспедиционной цепочке и `ctx.hasUI = true` команда fullscreen-дашборда SHALL открыть overlay с полной картой экспедиции, собранной из файлов (журнал цепочки, state/brief/log кампании, evidence): секции MAP (каждое направление: глиф статуса, имя, основание, refs, активная кампания), CAMPAIGN (вопросы кампании: id, вердикт, правило, причина; открытые — без вердикта), EVIDENCE (имена файлов кампании), TIMELINE (события карты с обоснованиями; не более 200 последних) и футер счётчиков. Поверхность SHALL быть read-only: никакие файлы не изменяются. Направление `advisory_exhausted` SHALL сопровождаться пометкой «самоотчёт, не доказательство». При повреждённом или нечитаемом журнале цепочки overlay SHALL показать одно сообщение о повреждении без краша. Вне экспедиции команда SHALL вести себя как существующий fullscreen-дашборд обычного цикла без изменений. В headless (без UI) команда SHALL ответить отказом, как сейчас.

#### Scenario: Экспедиция активна — полная карта
- **WHEN** экспедиционная цепочка активна, владелец открывает fullscreen-дашборд
- **THEN** показаны секции MAP/CAMPAIGN/EVIDENCE/TIMELINE и футер счётчиков; advisory — с пометкой недоказанности; данные собраны из файлов

#### Scenario: Повреждённый журнал
- **WHEN** chain.json нечитаем или повреждён
- **THEN** overlay показывает одно сообщение о повреждении; краша и пустого экрана нет

#### Scenario: Обычный цикл без экспедиции — регресс
- **WHEN** экспедиции нет, есть результаты обычного цикла
- **THEN** открывается существующий дашборд экспериментов без изменений

#### Scenario: Обычный цикл пустой — регресс
- **WHEN** экспедиции нет, результатов нет
- **THEN** существующее уведомление «No experiments yet» сохранено

#### Scenario: Headless
- **WHEN** команда вызвана в сессии без UI
- **THEN** отказ как у существующей команды; виджет и оверлей не рендерятся

#### Scenario: Длинный таймлайн
- **WHEN** событий карты больше 200
- **THEN** показаны последние 200 и строка «… N more»

### Requirement: Транскрипт expedition-действий

`renderCall` тула `research` для expedition-действий SHALL рисовать читаемую строку действия по args (активация/закрытие/advisory/парковка/pivot: глиф, имя направления, обоснование, refs) без чтения файлов. Для действий вне экспедиции renderCall SHALL сохранить прежнее поведение. При отсутствующих или битых args SHALL рисоваться существующий заголовок (fail-soft).

#### Scenario: Активация направления
- **WHEN** агент вызывает research expedition activate с dir и why
- **THEN** строка тула показывает глиф активации, имя направления и обоснование

#### Scenario: Закрытие с refs
- **WHEN** агент вызывает resolve/reject с refs
- **THEN** строка показывает глиф, имя направления и источники-refs

#### Scenario: Pivot
- **WHEN** агент вызывает pivot from/to с reason
- **THEN** строка показывает «from → to» и причину

#### Scenario: Не-expedition-действия не изменились
- **WHEN** агент вызывает research start/status/report (не expedition)
- **THEN** рендер не отличается от прежнего (регресс не допускается)

#### Scenario: Битые args
- **WHEN** args отсутствуют или некорректны
- **THEN** рисуется обычный заголовок; ошибки нет

### Requirement: Web-дашборд экспедиции

При активной экспедиционной цепочке и `ctx.hasUI = true` команда web-дашборда SHALL сгенерировать страницу карты экспедиции (те же данные и секции, что fullscreen) на существующем локальном static-сервере и открыть её в браузере. Для данных страницы SHALL быть добавлен маршрут «/expedition», отдающий JSON текущего view (собранного на лету; при повреждённом журнале — JSON с признаком повреждения). Страница SHALL обновлять данные двумя путями без новых broadcast-точек: по существующему SSE-сигналу «jsonl-updated» и по таймеру опроса 10 секунд. При `ctx.hasUI = false` и активной экспедиции команда SHALL ответить отказом (НОВОЕ поведение, только в expedition-ветке) и НЕ поднимать сервер. Вне экспедиции команда SHALL вести прежний ledger-дашборд без изменений, включая текущее отсутствие UI-гейта и текст ошибки «run some experiments first». Страница SHALL быть read-only и слушать только на localhost. Повторный вызов SHALL следовать контракту существующего сервера: тот же workDir — переиспользование сервера и прежнего URL; другой workDir — закрытие старого сервера, новый URL.

#### Scenario: Экспедиция активна
- **WHEN** экспедиция активна, владелец вызывает web-дашборд в TUI
- **THEN** браузер открыт на странице карты: направления, таймлайн, вопросы, счётчики; маршрут «/expedition» отдаёт JSON view

#### Scenario: Вне экспедиции — регресс
- **WHEN** экспедиции нет
- **THEN** прежний ledger-дашборд без изменений (включая текст ошибки «run some experiments first»); UI-гейт в эту ветку не добавлялся

#### Scenario: Headless в экспедиции
- **WHEN** экспедиция активна, команда вызвана при ctx.hasUI = false
- **THEN** уведомление-отказ; сервер не поднимается, страница не генерируется (НОВОЕ поведение expedition-ветки)

#### Scenario: Повреждённый журнал
- **WHEN** chain.json повреждён
- **THEN** маршрут «/expedition» отдаёт JSON с признаком повреждения; страница показывает сообщение о повреждении; сервер не падает

#### Scenario: Повторный вызов, тот же workDir
- **WHEN** web-дашборд уже поднят для этого workDir и вызван повторно
- **THEN** сервер переиспользован; уведомление показывает прежний URL

#### Scenario: Повторный вызов, другой workDir
- **WHEN** web-дашборд поднят для другого workDir и вызван для нового
- **THEN** прежний сервер закрыт, поднят новый; уведомление показывает новый URL

#### Scenario: Живое обновление
- **WHEN** экспедиционные данные меняются (запись в журнал/лог кампании)
- **THEN** страница обновляет карту не позднее 10 секунд (SSE-сигнал или таймер опроса); новые broadcast-точки для экспедиционных файлов не требуются
