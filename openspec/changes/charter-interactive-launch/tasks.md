## 1. Инструмент research_charter (draft + propose)

- [x] 1.1 Реализация + тесты: инструмент `research_charter` с действиями `draft`/`propose`.
  Тесты: draft с валидной хартией сохраняет черновик в runtime и не создаёт журнала/кампании/файла/режима; draft с хартией вне состава (неизвестное поле, лимит ниже порога, недопустимое стоп-правило) — именованный отказ без изменений состояния; поля одобрения/хеши в вызове отклоняются; повторный draft заменяет черновик; draft/propose без открытого диалога о хартии — отказ; propose без черновика — отказ; при активной цепочке инструмент отказывает целиком.

## 2. Propose: диалог, запись, фиксация-запуск

- [x] 2.1 Реализация + тесты: диалог и атомарная фиксация-запуск.
  Тесты: диалог начинается с «Charter SHA-256: <hex>» от хеша канонической сериализации черновика; нет UI (`ctx.ui.confirm` удалён) — отказ, ничего не создано; ответ не `true` — файл не записан, черновик жив, повторный propose снова показывает диалог; ответ `true` — полный путь: файл записан вне рабочего каталога (wx), перечитан, хеш сверен, корень пиннут (`--id` уважается, без него генерируется `bench-*`), журнал `<корень>-chain` создан, режим включён, кикофф отправлен; расхождение перечитанного хеша (симуляция мутации буфера записи) — отказ `charter_changed`, файл удалён, состояния нет; коллизия имени файла — отказ `charter_path_taken`, существующий файл не тронут; отказ createCampaign/createChain после записи — ПОЛНЫЙ откат: файл, каталог кампании и каталог журнала удалены, runtime и режим не изменены, причина названа; повторный propose после успеха (без нового черновика) возвращает первую фиксацию без диалога, второй цепочки нет.

## 3. Команда /autoresearch charter

- [x] 3.1 Реализация + тесты: подкоманда команды autoresearch.
  Тесты: команда с описанием открывает диалог о хартии и шлёт инструкцию агенту, research-режим не включается; без описания — именованный отказ с подсказкой; при активной цепочке или research-кампании — отказ на входе без черновика; конфликт, возникший между входом и propose, останавливает propose (файл не пишется).

## 4. Интеграция и регрессия

- [x] 4.1 Тест: интеграционный прогон — от `/autoresearch charter` через draft/propose до корневого бриф-диалога («Brief SHA-256»), старт, отчёт → `awaiting_child`, дочерний бриф автоподтверждён; отдельный шаг: изменение файла хартии после запуска → следующее действие цепочки отказывает с `charter_changed`, статус `manual_check_required` (сценарий «Файл подменён после запуска»); повторный `/autoresearch charter` при живом черновике — диалог открывается заново, новый draft заменяет старый (сценарий «Новый запуск при живом черновике»).
