# Proposal

## Why

Запуск исследовательской цепочки (research-charter) сегодня требует, чтобы владелец вручную написал JSON-файл хартии за пределами рабочего каталога, придумал id корневой кампании и повторил путь файла в флагах запуска (`/autoresearch research --charter <путь> --id <корень>`). Это барьер входа: легко ошибиться в пути/JSON/имени цепочки, а сам процесс согласования рамок не диалоговый. Остальные согласования проекта (бриф кампании, optimize-бриф) уже идут двухфазно (draft → диалог владельца с хешем), и хартия — единственное согласование, оставшееся ручным.

## What Changes

- Новая команда `/autoresearch charter [описание]`: двухфазное интерактивное формирование хартии агентом по словам владельца, по образцу research_brief draft → propose:
  - фаза **draft**: агент формирует объект хартии по описанию владельца и сохраняет черновик; система валидирует состав (allowlist полей, лимиты ≥ порогов, стоп-правила не трогают вердикты/evidence_gate/caveat), отказ с именованной причиной — ничего не пишется;
  - фаза **propose**: диалог владельца с первой строкой «Charter SHA-256: <hex>» (те же байты, что на диске), строго `true` фиксирует хартию: файл записывается за пределами рабочего каталога, запись фиксирует перехешированный файл, повторный propose возвращает первую фиксацию.
- После фиксации хартии команда **сразу запускает цепочку**: создаёт журнал цепочки (`<корень цепочек>`), пиннит корневую кампанию (`--id` генерируется, если не указан), включает research-режим и отправляет бриф-кикофф — та же точка входа, что `/autoresearch research --charter --id`, чтобы дальнейшее поведение (диалог корневого брифа, автоподтверждение детей, отчёты, chain_stop) не дублировалось.
- Путь хартии и его hash фиксируются в runtime и ревно перечитываются на каждом действии цепочки (как сейчас): подмена файла после одобрения → `charter_changed` + `manual_check_required`.
- Конфликты состояния: активная цепочка, активная кампания в research-режиме — именованные отказы, ничего не стартует; повторный запуск команды при живом черновике открывает диалог заново (замена черновика); черновик хартии не создаёт ни журнала, ни кампании, ни режима.
- Вне области: параллельные цепочки, редактирование принятой хартии командой (правка = новый двухфазный цикл с новым файлом), headless-флаги (обёртка `research-rpc.mjs` остаётся на `--charter/--approve-charter-sha`).

## Capabilities

### New Capabilities

- `charter-launch`: двухфазное интерактивное согласование хартии (draft → диалог владельца) и запуск цепочки из одной команды; владение «согласование рамок цепочки».

### Modified Capabilities

- Пусто — замороженные требования research-charter не меняются. Запуск цепочки из charter-команды повторно использует существующие требования (бриф-диалог корня, автоподтверждение детей, отчёты, chain_stop, перечитывание файла хартии) по ссылке; интерактивный вход описан новой способностью charter-launch как ADD-дельта.
