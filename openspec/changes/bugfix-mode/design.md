# Design: bugfix-mode (draft, rev.3)

## Context

`.auto/measure.sh:3-79` — измеритель одной кампании, а не часть установленного пакета. `brief-tools.ts:54-120` привязывает старт обычной оптимизации к одобренному брифу; `log-experiment-tool.ts:768-790` при keep выполняет `git add -A` и commit. Его rollback при discard способен затронуть рабочее дерево. Спеки `optimize-brief-consent` и `measurement-track` продолжают действовать. Утверждение, что сам `init_experiment` переписывает все скрипты, не установлено: риск — подготовка новой цели может их заменить.

## Goals / Non-Goals

Цель — описать воспроизводимый bugfix-режим с метрикой и управлением поиском; отделить переносимую логику измерителя от кампании. Не цели — реализация в текущем задании, универсальные профили или перенос `.auto` целиком.

## Decisions

### Источник и версия

Предложение: эталонная версия логики и правил метрики поставляется в пакете pi-autoresearch как версия bugfix-измерителя, независимо от `.auto` отдельного проекта. Каждая кампания фиксирует версию и применённые настройки; новая версия не изменяет существующую шкалу незаметно. Копирование в `.auto` само по себе не является сохранением оригинала. Где и как хранить экземпляры нескольких кампаний и как переключаться между ними — уточнить в дизайне запуска; нельзя обещать возобновление старой кампании без сохранения её runner, параметров, ledger и результатов.

### Инвентаризация текущей метрики

Из `.auto/measure.sh:19-69`:

| Компонент | Сейчас | При переносе |
|---|---|---|
| Награда | `10 * weighted / sqrt(1+0.35*(n-1))`, P1=1, P2=0.7, P3=0.3; n=0 даёт 0 | v2 делит ту же сумму на `N` за подтверждённую находку и `2N` за зачтенный фикс; decay применяется к объединённому числу дефектов |
| Регрессии | `-fail -5*max(0,fail-6)` | сохранить при исходных параметрах; baseline failures получать для проекта. Это разница количества, а не доказательство отсутствия новых падений |
| Объём | `-0.05*max(0,changed-200*n)` | 200 — правило текущей формулы, scope и base ref — параметры кампании; учитывать ограничения подсчёта git diff |
| Измеритель | `-20*scorer_changed` по git diff | сохранить намерение, но `git diff` не замечает неотслеживаемые `.auto` файлы; нужен контроль объявленных файлов и честное сообщение о неполноте согласно measurement-track |
| Пруфы | `-10*invalid`; credit при `status=keep`, `mutation_red` и `guard_restored` | сейчас `invalid` — все строки, не прошедшие фильтр, включая discard, а не только ошибочные пруфы; в предлагаемой версии обычный discard не штрафуется. Флаги — самоотчёт. Претендент на награду требует проверок, связанных с экспериментом, без обещаний абсолютной защиты от подделки |
| Тесты | `+0.02*max(0,tests-2031)` | в v2 бонус дают только безопасные идентификаторы `[A-Za-z0-9._/-]`, для которых режим сам исполняет шаблон `testIdCommand` в обоих состояниях и получил разные исходы: `+0.1*min(3,detector)` и `+0.1*min(3,proof)`; общее число тестов остаётся диагностикой |

Решение v2: находка оплачивается в момент подтверждения и не отзывается последующим discard — это сохраняет мотивацию искать. Повторный зачёт невозможен из-за глобального дедупа по `defectId`; механика принудительного фикса или сгорания кредита не нужна, потому что выплата за фикс вдвое больше и дефекты конечны. Полный пруф по-прежнему требуется только для награды за фикс.

Проектные вводы: корень, команда тестов, формат и парсер результатов, рабочий каталог и временные файлы; git base ref, пути оценки diff, базовые `fail` и `tests`; пути и идентичность измерителя и ledger. В оригинале заданы `D:/...`, `D:/tmp`, `npm test`, TAP, `9fba532`, `extensions tests`, `6`, `2031` (`.auto/measure.sh:3-15,36-52`). Нельзя выдавать эти значения за универсальные. Одного exit code недостаточно для извлечения чисел тестов; при неподдерживаемом формате или отсутствии полного результата измерение должно быть явно недействительным, а не «0 ошибок». Коэффициенты — значения предложенной версии, не физические константы.

### Цикл и запуск (проект, не реализация)

Согласование цели и первоначальный замер → поиск неизвестного дефекта → гипотеза и воспроизведение → фикс и проверка контрфакта → измерение → существующие `run_experiment` и `log_experiment` → учёт результата и выбор следующего поиска. Предварительная оценка кандидата включает только прошедший проверки кандидатский credit и помечается предварительной; в историю лучших результатов она попадает только после keep. Привязка по идентификатору прогона к решению обеспечивает, что discard, ошибка или прерывание не дают постоянного credit. Способ атомарной записи остаётся предметом реализации с тестами на прерывание. Существующие гейты брифа, исследовательского режима и кандидатных веток не обходятся. Минимальный защитный вариант для MVP — отказ до запуска при незакоммиченных отслеживаемых или неигнорируемых неотслеживаемых файлах; отдельно защищаются существующие данные `.auto`, которые git не учитывает. Проверку повторяют перед потенциально разрушительными git-операциями; конкурирующие изменения требуют отказа, а не их удаления. Гарантия относится к операциям самого режима: игнорируемые пользовательские файлы режим не добавляет и не удаляет. Произвольные команды проекта могут менять любые доступные им файлы, поэтому их безопасность не гарантируется.

При переключении цели пакетный эталон остаётся доступен; сохранение конкретной кампании и восстановление её контекста — отдельное требование, не следствие наличия шаблона. Изменение действующего измерителя идёт через существующий measurement-track с учётом шкал и проверкой. Для сигнала продолжения используются существующие `tree_status` и `direction_review`; отдельное действие `continue` в режим не входит. Стагнация или finalize сами по себе не доказывают исчерпание поиска.

### Разделение работы

Эта ревизия — только проект и разбор. Позже реализация: портировать scorer на зафиксированных входных данных и проверить эквивалентность исходной формуле, затем определить и реализовать подготовку кампании и подключение цикла. Не брать контроль режима или новую логику за уже существующую.

## Risks / Trade-offs

- [Награда без реальной проверки] → минимальный контракт: проверочные команды фиксируются в конфигурации кампании и не принимаются от агента на каждом эксперименте; режим сам их запускает, метки состояний обязаны разрешаться в реальные git-коммиты, а артефакт содержит команды, коды выхода, флаг прерывания, вывод, идентификатор эксперимента и разрешённые SHA. Для зачёта проверяются ожидаемые исходы, привязка к кандидату и полнота артефактов. Каждая проверка выполняется режимом в отдельном detached worktree соответствующего коммита, который удаляется в `finally`; рабочее дерево пользователя не переключается. Таймаут не считается ожидаемым падением. Проверки, требующие некоммитнутых зависимостей проекта, в этой версии не поддерживаются. Самоотчёт агента не заменяет запуск. Это не защита от намеренно поддельной команды в конфигурации или манипуляции окружением; независимое ревью остаётся нужно для оценки смысла теста.
- [Несколько credit на одно решение] → один `keep` начисляет не более одной награды на эксперимент, даже если записано несколько пруфов с разными ID дефектов; повтор дефекта тоже не начисляет.
- [Повторное начисление] → повторный идентификатор дефекта или тот же пруф не должны увеличивать reward; семантические дубликаты требуют ревью, одного идентификатора недостаточно.
- [Штраф за исследование] → учитывать отклонённые кандидаты без credit и без `invalid` штрафа. Это намеренное отличие от нынешней формулы, значит новая версия не сопоставима со старой без пересчёта.
- [Регрессии скрыты одинаковым числом падений] → считать число недостаточным для установления идентичности ошибок; сравнивать идентификаторы или явно показывать ограничение поддержки формата.
- [Текущая формула поощряет тесты и защиту scorer] → выявлять переобучение на независимых проектах и анализировать отдельные составляющие, не обещать, что high score означает пользу.
- [Грязное дерево] → до запуска защитить пользовательские изменения; git add -A и rollback обычного цикла не считать безопасными по умолчанию.
- [Сломанный runner возвращает exit 0] → новая интеграция не должна принимать отсутствие разбора как валидный замер; старое поведение не меняется в текущей кампании.

## Migration Plan

Текущие `.auto/measure.sh`, ledger и история остаются нетронутыми. Новые режим и шаблон добавляются после отдельного утверждения; старые результаты разных шкал не сравниваются. При отказе от нового режима используется существующий optimize без переписывания прежних кампаний.

## Open Questions

До реализации уточнить минимальный поддерживаемый формат тестовых результатов, детали выполнения и идентификации состояний для проверки контрфакта и сохранение экземпляров кампаний. Контракт защиты дерева при реализации обязан различать существовавшие до запуска игнорируемые файлы и файлы, созданные или изменённые командами кампании. Это существенные вопросы контракта: данный draft не является разрешением на реализацию.
