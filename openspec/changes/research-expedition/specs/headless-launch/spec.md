# headless-launch: expedition запуск

## ADDED Requirements

### Requirement: Headless-запуск экспедиции

Обёртка `scripts/research-rpc.mjs` SHALL принимать `--expedition-doc <путь>` и `--approve-expedition-sha <hex 64 символа в нижнем регистре>` для запуска экспедиции; аргументы взаимно обязательны: отсутствие любого — ошибка разбора (exit 2) до запуска pi, без создания состояния. Они MUST быть взаимоисключающими с `--charter`, `--brief` и `--approve-sha` (одновременная передача — exit 2): согласие владельца покрывает документ целиком, включая бриф кампании №0, отдельное подтверждение брифа не запрашивается. Файл `--expedition-doc` MUST быть в канонической форме `JSON.stringify(JSON.parse(bytes), null, 2) + "\n"`: неканонический файл, непарсируемый JSON (включая пустой файл и BOM), отсутствующий файл, а также `--approve-expedition-sha` не по маске `^[0-9a-f]{64}$` — отказ (exit 2) до спавна pi. Согласование хеша экспедиции — трёхстороннее, по образцу брифа: диалоговый хеш из строки `Expedition SHA-256:`, операторский `--approve-expedition-sha` и пересчитанный из файла в момент ответа; любое несовпадение — ответ диалога `false` и код выхода 3, состояние не создаётся. Диалог `Expedition SHA-256:` MUST распознаваться отдельной регуляркой (префикс не пересекается с `Brief SHA-256:` и `Charter SHA-256:`). Последующие брифы цепочки автоподтверждаются по хартии документа. Промежуточный отчёт цепочки MUST NOT завершать запуск: обёртка доставляет продолжение; завершение хода агента в статусе `awaiting_child` — штатный код 0, состояние сохраняется. Коды выхода существующих сценариев не меняются; без `--expedition-doc` поведение обёртки прежнее.

#### Scenario: Запуск экспедиции в headless
- **WHEN** обёртка запущена с `--expedition-doc` и совпадающим `--approve-expedition-sha`, диалог `Expedition SHA-256:` распознан и отвечен `true`
- **THEN** экспедиционная цепочка стартует без интерактивных диалогов и без `--brief`/`--approve-sha`; промежуточные отчёты не завершают сеанс; пауза `awaiting_child` — код 0

#### Scenario: Отказ документа экспедиции
- **WHEN** хеш документа не совпал или диалог `Expedition SHA-256:` ответил не `true`
- **THEN** ответ диалога `false`, код выхода 3, состояние не создаётся

#### Scenario: Каноническая форма документа
- **WHEN** байты `--expedition-doc` не равны канонической форме, или файл отсутствует, или JSON не парсится (пустой файл, BOM)
- **THEN** ошибка аргументов (exit 2) до запуска pi

#### Scenario: Взаимоисключающие режимы
- **WHEN** обёртка запущена одновременно с `--expedition-doc` и любым из `--charter`, `--brief`, `--approve-sha`
- **THEN** ошибка аргументов (exit 2) до запуска pi

#### Scenario: Неполная пара аргументов
- **WHEN** `--expedition-doc` передан без `--approve-expedition-sha` (или наоборот)
- **THEN** ошибка разбора аргументов до запуска pi, состояние не создаётся

## MODIFIED Requirements

### Requirement: Research-режим требует канонический бриф и хеш

`--mode research` MUST требовать `--brief` и `--approve-sha`; без них — ошибка аргументов (exit 2) до спавна pi. Файл `--brief` MUST быть в канонической форме `JSON.stringify(JSON.parse(bytes), null, 2) + "\n"`; неканонический файл, непарсируемый JSON (включая пустой файл и BOM), отсутствующий файл, а также `--approve-sha` не по маске `^[0-9a-f]{64}$` или `--campaign-id` не по маске `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` — отказ (exit 2) до спавна pi. Исключение — запуск экспедиции: при переданном `--expedition-doc` аргументы `--brief` и `--approve-sha` MUST NOT требоваться и MUST отклоняться вместе с ним (взаимоисключающие, exit 2): согласие владельца покрывает документ целиком, включая бриф кампании №0.

#### Scenario: Запуск без брифа
- **WHEN** скрипт вызван с `--mode research` без `--expedition-doc` и без `--brief` или без `--approve-sha`
- **THEN** завершение с ошибкой аргументов (exit 2); pi не запускается.

#### Scenario: Неканонический или непарсируемый бриф
- **WHEN** байты `--brief` не равны канонической форме, или файл отсутствует, или JSON не парсится (пустой файл, BOM)
- **THEN** завершение с ошибкой (exit 2) до спавна pi.

#### Scenario: Невалидный approve-sha или campaign-id
- **WHEN** `--approve-sha` не по `^[0-9a-f]{64}$` или `--campaign-id` не по `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`
- **THEN** завершение с ошибкой (exit 2) до спавна pi.

#### Scenario: Бриф при запуске экспедиции
- **WHEN** скрипт вызван с `--expedition-doc` и при этом с `--brief` или `--approve-sha`
- **THEN** завершение с ошибкой аргументов (exit 2) до спавна pi; отдельное подтверждение брифа №0 не существует — согласие покрывает документ целиком.

#### Scenario: Stage 2 при стриминге
- **WHEN** stage-2 prompt отправлен во время стриминга (не должен происходить при верном sequencing) и вернулся `queued` или `success:false`
- **THEN** ошибка обёртки: exit 1, причина в логе.
