## 2. Фаза исследования
- [ ] 2.1 Действие `research(start)` с ожидаемым хешем. Тесты: совпадение запускает фазу; несовпадение даёт brief_changed.
- [ ] 2.2 Проверка неизменности брифа на каждом действии. Тест: правка брифа после подтверждения блокирует все действия.
- [ ] 2.3 Действие `open`: только вопросы брифа, один активный вектор, без переоткрытия. Тесты по каждому отказу.
- [ ] 2.4 Действие `record`: доказательство путь:строки или путь#якорь, SHA-256 файла в журнал. Тесты: отсутствие файла даёт отказ; изменение файла после записи помечается.
- [ ] 2.5 Действие `close`: rule_id из брифа, совпадение с вердиктом, причина для inconclusive и waiting_for_data. Тесты: чужой rule_id, несовпадение вердикта, отсутствие доказательства.
- [ ] 2.6 Действие `stop` по стоп-правилу брифа; после срабатывания открытие отказывает. Тест.
- [ ] 2.7 Действия `status` и `report`: статусы вопросов, проверка хешей, блок ограничений дословно; доступны после остановки. Тесты на содержимое отчёта.
- [ ] 2.8 `resolve` для ручного восстановления через подтверждение оператора; тесты отказа без UI и при отсутствии согласия. Новая кампания не перезаписывает старую.
