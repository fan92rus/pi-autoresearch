# Design

## Решения

1. **Единицы шума.** `calibrateNoiseFloor` возвращает долю. Перед записью её переводят в абсолютное значение: `noiseFloor = fraction × baselineMetric`. В конфиг добавляется `noiseFloorUnit: "metric"`. Совет и `validateSlate` читают только `noiseFloor` при наличии маркера. Старые конфиги без маркера считаются «не откалиброваны» (fail open для гейта, видимое предупреждение).

2. **Источник шума.** Confidence = `|best − baseline| / sd`, где `sd` — стандартное отклонение повторов лучшей гипотезы. Нужно минимум два значения одной гипотезы. MAD сегмента сохраняется только как диагностика. Калибровочный холостой прогон остаётся, но его значение не используется как `sd`: это одна пара, а не разброс.

3. **Статус keep (без отказов).** `log_experiment` никогда не отклоняет keep из-за отсутствия повтора. Статус:
   - «подтверждён», если confidence известен и ≥ 2×, либо есть повтор той же гипотезы (`hypothesis_id`), лучший базы;
   - «предварительный» в остальных случаях, включая первый прогон без confidence.
   Keep коммитится в обоих случаях, как и сейчас. Порог 2× — значение по умолчанию, в конфиге не меняется в MVP.

4. **Повторы необязательны.** Агент может повторить гипотезу, но система ничего не требует. Это решение владельца: в MVP обязательных повторов нет, в том числе для тестов короче минуты.

5. **Отчёт и статус.** Счётчики считаются из ledger в активной эпохе. Лучший keep показывается с его статусом из решения 3.

6. **Совместимость.** Существующие записи ledger не переписываются. Для старых keep статус выводится по тем же правилам из текущих данных; где повторов нет, он предварительный.

## Решённые вопросы (владелец, 2026-11-10)

- Первый keep без повтора разрешён; помечается как предварительный.
- Обязательных повторов в MVP нет; вопрос про короткие тесты (≤ 1 мин) отложен до опыта.

## Вне MVP

Многократная калибровка шума (n ≥ 5), обязательные повторы, предрегистрация, роли данных — см. proposal, «Out of scope».
